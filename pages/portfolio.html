HOW THE WORK IS MADE

研究判断 → 工程治理 → 框架沉淀 → 游戏验证

查看研究记录

Myosotis 保存判断，Iris Engineering 约束授权与执行，Violet Shelf 提供独立本地入口，SakuraGameFramework 与 Iris Core 沉淀可复用能力，UDGAP、The Weaver 与《言铸之剑》承担不同阶段的游戏验证。

  1. 01

    研究判断

    理解引擎机制、游戏设计与当前约束。

  2. 02

    显式授权

    把研究提案、目标和执行权限变成可复查合同。

  3. 03

    框架沉淀

    只把跨项目复用的结论沉淀为稳定边界。

  4. 04

    游戏验证

    用可玩循环、截图和限制校验实际价值。

03 · 《杀戮尖塔 2》角色 Mod · 三幕 Headless 验证通过

Iris × Sakura — The Weaver

更新 · 2026-09-03

Iris Core 的首个玩法 Consumer：以 Iris / Sakura 双形态与 Node、Compile、Bloom、Handoff、Dual 组成可切换的构筑循环，已完成 106 张卡、13 件遗物和 3 瓶药水的程序内容。

职责
原创角色 / 卡牌与战斗系统开发
目标
用一个真实卡牌角色验证双形态状态机、玩家局部持久化、内容池治理与可扩展机制能否共同稳定运行。
开发详情
证据
62 项机制与内容门禁，106 张卡均有逐卡效果合同；95 张奖励牌、5 张 Pinned 起始牌、6 张 GeneratedOnly 派生牌的内容选择快照；default / reduced / experimental-heavy 三个独立 Headless 完整局均通过三幕、Architect 胜利与返回主菜单；Release / Debug、双语本地化、PCK 资源门禁和 8 套 Debug Deck

04 · STS2 模组基础设施 · 本地构建与封包通过

Iris Core

更新 · 2026-09-03

面向 Iris / Sakura《杀戮尖塔 2》模组的独立共享运行时，统一管理模块生命周期、配置、存储、诊断、内容选择与 Iris Hub；单独启用时不注册或修改玩法内容。

职责
共享运行时 / 模组控制平面
目标
让多个 STS2 模组共用一套可观测、可配置、可恢复的运行与内容控制边界，而不把具体玩法泄漏进 Core。
开发详情
证据
52 项 Core 测试与中性性静态门禁；Release / Debug 构建与 IrisCore PCK 资源门禁；Content Registry、Selection Snapshot / Hash、Profile 可见性和 Iris Hub 合同
限制
当前未作为独立公开下载版发布；现有证据是本地构建、合同与封包，不等同于远端 Runner 或公开发行
下一步
在新 Consumer 中验证通用扩展边界；为同一提交补充远端 Runner 与公开发行证据；在独立发布门禁下整理安装与升级路径

FRAMEWORK PLAYGROUNDS

七个独立玩法项目

七个独立 Unity 项目分别探索塔防、时间管理、工厂物流、生态收集、刷装战斗、生活模拟与双模式战斗，让 Framework 能力落到可理解、可运行的玩法循环里。

7 个玩法案例

01塔防原型

Route-Wave TD

建塔、封锁路线与三波敌人组成一局紧凑的塔防循环；结束后可以清理状态并开启全新战局。

核心系统

  • 路线封锁
  • 波次推进
  • 建造窗口
  • 胜负结算

02时间管理原型

Kitchen Shift

在一个短班次里安排多道菜并同时服务顾客；配方前置、等待与流失共同形成时间压力。

核心系统

  • 并行烹饪
  • 配方前置
  • 顾客耐心
  • 班次结算
03工厂物流原型

Railworks Factory

围绕铁路联运组织生产与发运；堵塞出现时恢复调度，并控制持续运行产生的历史记录。

核心系统

  • 生产排程
  • 铁路发运
  • 堵塞恢复
  • 历史清理
04生态收集原型

Living Bestiary

在季节推进中模拟生态变化和生物遭遇，并用检查点存档与备份恢复延续探索进度。

核心系统

  • 季节循环
  • 生物遭遇
  • 检查点存档
  • 备份恢复
05刷装战斗原型

Ashfall Loot Run

在三次遭遇中用确定性掉落和伤害预算完成一轮刷装；权威拾取与重复拒绝让战利品状态保持可信。

核心系统
