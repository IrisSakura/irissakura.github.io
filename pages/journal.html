框架审计 · 2026-08-01

Sakura Framework 仓库最新审计与能力收敛计划

自上一轮审计基准以来，默认分支新增了四个主要提交，集中完成三组能力： Artifact Manifest Foundation：建立本地、未签名的 Artifact 完整性清单； Wasm Component Runtime 与隔离编译：加入 Provider-neutral Component 合同、Wasmtime Host、Modding typed session、一次性 helper process 和 Semantic Battle 真实消费链； AI 与 LLM 运行时边界修复：修复行为树生命周期、黑板类型覆盖、GOAP 最低成本保证、非有限数值输入、结构化模型输出和异步 AI Director 生命周期。 最新提交重点修复了： AIBlackboard 同一 Key 同时残留在多种类型存储中的问题；

框架审计 · 2026-07-31

Sakura Framework 仓库最新审计与能力收敛计划

本轮默认分支较上一轮新增了 12 个提交，主要完成了五组能力： Compile-time Contracts P0：引入 Roslyn Analyzer，对 Engine-Agnostic Core 的程序集边界进行编译期检查。 LLM 0.8.0：建立异步主协议、短期凭据、结构化输出、命令事务和可信执行边界。 Verification Laboratory P0：增加确定性属性测试、Shrink 和最小失败制品。 Deterministic Replay Foundation：将 Simulation 回放协议升级为带 Header 和 Typed Records 的 schema v2。 Trace Context / Observability Foundation：在 Core 包内增加引擎无关 Trace Context、Span 和有界内存 Provider。

框架审计 · 2026-07-30

Sakura Framework 仓库最新审计与能力收敛计划

本轮仓库变化集中在三条主线上： Modding 与热更新能力大幅扩展：原 Modding 包被拆为 Core、Unity、Code、HybridCLR 四个职责包，原包转为兼容聚合入口；同时建立在线更新事务、不可变版本目录、信任校验、Wasm/Lua、受控托管代码、HybridCLR 使用环境和 Editor Guided Recipe。 跨平台工程链继续加固：近期提交集中修复 Runtime、Editor Tools、Server、Node 工具和 CI Workflow 的路径与宿主兼容性，并增强 Unity 失败摘要保留。 Sample 测试选择问题被修复：最新提交修复了环境变量中的普通 Unity Impact 包集合覆盖 Runtime Starter 动态依赖发现的问题，使 Sample 可以重新安装 Save、Config、Audio、UI 等真实闭包。
