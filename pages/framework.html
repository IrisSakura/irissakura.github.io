MATURITY BEFORE SCALE

先看成熟度，再看规模

146 个 Package 中只有 4 个处于 Supported；Preview 和 Experimental 不应被解释为同等稳定的生产能力。

4Supported

具备稳定使用边界、验证证据与维护承诺。

105Preview

方向已建立，但 API、集成路线或证据仍可能变化。

25Experimental

用于验证设计假设，不应默认进入生产依赖。

9DocsOnly

只提供设计、文档或使用指导，不计入运行时能力。

3Frozen

保留兼容与历史用途，不再主动扩展。

升级到 Supported 的公开条件

  • 职责、依赖闭包和兼容边界明确；
  • 具备对应测试、文档和真实采用证据；
  • 破坏性变更、迁移与维护承诺可说明。

新项目如何采用

先用 Core Only 验证基础契约与编译，再以 Bootstrap Lite 增加 Event、GameHelper 和 Pooling；只有明确需要时才评估 Preview 能力。

与《言铸之剑》的关系

采用映射只记录项目依赖清单与源码引用能够证明的实际使用；它不改变任何包的生命周期，也不把 Preview 能力包装成 Supported。
