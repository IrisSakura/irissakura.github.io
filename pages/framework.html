SAKURA FRAMEWORK · ENGINEERING PORTFOLIO

为什么持续做这个框架

把在游戏中反复使用的运行时服务与玩法能力整理好，让下一次实验和创作可以从已经解决的问题出发。

WHY I BUILT IT

让下一次创作有一个更好的起点

存档、事件、资源、时间、战斗和 UI，是做游戏时会反复遇到的问题。我把其中能复用的部分整理成模块，希望把更多注意力留给具体的游戏。

在《言铸之剑》中，这些模块参与了房间推进、战斗与构筑。独立玩法实验则帮助我观察它们在不同规则下怎样协作。

升级到 Supported 的公开条件

  • 职责、依赖闭包和兼容边界明确；
  • 具备对应测试、文档和真实采用证据；
  • 破坏性变更、迁移与维护承诺可说明。

新项目如何采用

先用 Core Only 验证基础契约与编译，再以 Bootstrap Lite 增加 Event、GameHelper 和 Pooling；只有明确需要时才评估 Preview 能力。

与《言铸之剑》的关系

采用映射只记录项目依赖清单与源码引用能够证明的实际使用；它不改变任何包的生命周期，也不把 Preview 能力包装成 Supported。

通过强类型窗口串联加载、显示、用户结果与关闭清理，支持直接更新、属性绑定和可选 MVVM；文本从 Unity String Tables 解析并随语言切换更新。项目提供窗口资源、注册表与翻译表，窗口和应用各自释放所拥有的资源。

online-foundation

Online Foundation

从有界本地 Mock Backend 获取 Session、Party 和匹配 Assignment，连接真实 TCP 并校验权威快照，以确定性模拟完成预测对账、Replay 与结果幂等提交。项目拥有连接、模拟和退出清理；生产 Backend、账户数据库与第三方 SDK 需由项目另行集成。

core→command→networking→simulation→online

content-interaction-foundation

Content Interaction Foundation

通过可交互对象启动剧情对话与分支演出，依据已确认的剧情事件解锁图鉴，支持字幕本地化、存档恢复和图标资源清理。项目提供具体 UI、剧情内容与演出。

core→pooling→gamehelper→event→preferences→asset→localization→interaction→dialogue→codex

world-progression-foundation

World Progression Foundation

从玩家位置加载区块，保存建造与库存变化，以离散日历结算已提交的世界事实，再查询科技条件并确认本地成长操作。项目提供地图、资源、科技内容与状态 Owner；多人服务和数据库事务由项目另行集成。

core→pooling→gamehelper→event→asset→parallel→save→ledger→economy→survival→calendar→tech-tree

configured-service-foundation

Configured Service Foundation

把经过迁移和校验的配置快照用于创建服务队列，观察排队、完成、拒绝与清理结果。项目提供配置内容、队列规则和 Session Owner；新快照用于下一次装配，运行中的队列由项目决定迁移方式。
