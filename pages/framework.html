SAKURA FRAMEWORK · ENGINEERING PORTFOLIO

从模块集合到工程判断

Sakura Framework 将可迁移的游戏语义留在 Portable Core，把引擎差异收敛到 Adapter，并用 Ownership、治理规则与证据边界约束每一次扩展。

边界这里展示的是架构方向与已公开证据，不把 Godot Runtime Host、完整 Godot Core / Config 或 Runner 尚未闭合的部分包装成已交付能力。

升级到 Supported 的公开条件

  • 职责、依赖闭包和兼容边界明确；
  • 具备对应测试、文档和真实采用证据；
  • 破坏性变更、迁移与维护承诺可说明。

新项目如何采用

先用 Core Only 验证基础契约与编译，再以 Bootstrap Lite 增加 Event、GameHelper 和 Pooling；只有明确需要时才评估 Preview 能力。

与《言铸之剑》的关系

采用映射只记录项目依赖清单与源码引用能够证明的实际使用；它不改变任何包的生命周期，也不把 Preview 能力包装成 Supported。

START SMALL, VERIFY FIRST

6 个 Supported 包与最小采用路线

Supported 统计按包计算，不把 Preview 模块包装成稳定能力。新项目应先验证最小闭包，再按需求扩展。

  • Corecom.unitygame.framework.core

    低依赖基础契约与生命周期底座

  • Eventcom.unitygame.framework.event

    跨系统事件发布与订阅

  • GameHelpercom.unitygame.framework.gamehelper

    游戏启动与通用运行辅助

  • Poolingcom.unitygame.framework.pooling

    对象复用与生命周期回收

  • Bootstrapcom.unitygame.framework.bootstrap

    组合根、Scope 生命周期、可观察启动与任务监管

  • Preferencescom.unitygame.framework.preferences

    命名空间化强类型本地设置、显式刷新与旧键迁移
