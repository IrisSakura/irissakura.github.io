ARCHITECTURE AS CODE

Governance 不是文档口号，而是可执行边界

Package Identity、Layer、Dependency、Lifecycle 与 Evidence 由机器合同共同约束，例外必须带理由和恢复条件。

WHAT THIS SOLVES

解决什么

让 147 个包在持续演进时仍能回答谁可以依赖谁、什么可以晋级，以及失败后从哪里恢复。

WHAT THIS COSTS

付出什么

每次跨层变化都需要同步清单、测试、文档和生成投影，短期交付成本更高。

WHERE IT DOES NOT APPLY

哪里不适用

单仓库一次性原型不必复制完整治理面，但仍应保留最小 Ownership 与依赖方向。

FAILURE BEFORE HAPPY PATH

失败模型

01

README 数量漂移但仍被当成真理源

02

04

生成投影被手改并覆盖 Owner

TRADE-OFFS

代价与边界

01

治理优先降低长期维护面，但会增加变更前置检查

02

例外允许真实迁移，却必须可检索、可撤销

03

自动清单更可靠，但只能表达源数据确实拥有的事实
