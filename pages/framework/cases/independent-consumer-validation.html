CASE 05 · local-passed / runner-pending

Independent Consumer Validation

用固定双方提交验证真实引用，而不是用示例替代采用证据

阅读本页返回 Engineering Hub

local-passed / runner-pending用固定双方提交验证真实引用，而不是用示例替代采用证据

01

Problem

Framework 自测无法回答独立项目能否安装、组合、运行并清理这些能力。

02

Constraints

每个 Consumer 固定在不同 Framework commit；公开数据不能泄漏私有路径或把局部结果外推。

03

Naive Approach

统计 README 引用或只展示一个内部 Sample。

04

Architecture Decision

为七个 Consumer 固定 source/framework commits、包哈希、Unity 版本与局部 EditMode/PlayMode/Player 证据。

05

System Model

Consumer source 导出审查过的闭合事实；站点 importer 校验身份、哈希和新鲜度；Matrix 按假设展示。

06

Failure Model

提交混用、测试 XML 失败、包哈希漂移、证据过期或公开字段越界时拒绝导入。

07

Trade-offs

快照需要维护且不会自动追随 Framework main；换来可复核的独立消费边界。

08

Implementation

Route-Wave TD、Kitchen Shift、Railworks Factory、Living Bestiary、Ashfall Loot Run、Willow Hearth 与 Sakura Core Arena 已进入 registry。

09

Evidence

七个案例均记录 local-passed / runner-pending 及各自 EditMode、PlayMode 或 Player 范围。

10

Consumer

每个项目回答不同玩法与生命周期假设；具体游戏内容、数值和体验仍由 Consumer 拥有。

11

Known Limitations

这些是固定快照和本地证据，不代表所有包、当前 main 或 Production。

12

What Changed After Validation

验证后增加双方 commit、package hash、证据新鲜度和 fail-closed importer，移除仅凭文档的采用声明。
