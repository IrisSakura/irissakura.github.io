CASE 04 · local-passed / runner-pending

Card Balance Toolchain

同一数值语义穿过 Unity Editor、Godot Dock、CLI 与 STS2 Consumer

阅读本页返回 Engineering Hub

local-passed / runner-pending同一数值语义穿过 Unity Editor、Godot Dock、CLI 与 STS2 Consumer

01

Problem

卡牌数值审查若绑定单一 Editor 或表格格式，设计判断无法跨工具复用。

02

Constraints

核心必须 BCL-only；Excel/CSV、Unity、Godot 与 CLI 是不同 Adapter；诊断需要稳定代码和可重复输出。

03

Naive Approach

把规则写进 Unity EditorWindow，或让每个 Consumer 自己解析表格。

04

Architecture Decision

建立 Editor-only 但引擎无关的 Card Balance Core，由 Unity/Godot/CLI Adapter 负责输入、展示和导出。

05

System Model

Importer 产生标准记录；Analyzer 执行规则；Diagnostic Report 保留身份；Adapter 决定交互与文件系统。

06

Failure Model

列缺失、值域错误、重复身份、Adapter 输出漂移和 Consumer 卡牌集合变化都必须给出可定位诊断。

07

Trade-offs

维护多个 Adapter 和兼容层，但规则与诊断只存在一份。

08

Implementation

Core、Excel/CSV Unity Adapter、Godot Editor Dock、headless CLI 与 STS2 集成已经本地闭合。

09

Evidence

Unity Adapter、Editor profile、The Weaver 106 cards、Godot managed tests 与跨阶段 Node contracts 均有本地记录。

10

Consumer

The Weaver / STS2 提供真实卡牌集合与工作流反馈，证明工具不只服务示例数据。

11

Known Limitations

本轮没有同 SHA Runner、正式 Release、签名或公开生产使用证明。

12

What Changed After Validation

验证后把规则从 Unity Editor 中抽离，并补充稳定 Diagnostic identity、Godot Dock 和 headless 路线。
