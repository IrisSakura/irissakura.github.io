SAKURA FRAMEWORK ENGINEERING

Framework Evolution

演进不是模块数量曲线，而是边界、证据和恢复能力逐步收敛。

阅读本页返回 Engineering Hub

演进不是模块数量曲线，而是边界、证据和恢复能力逐步收敛。 时间线只展示公开工程变化，不投影内部 PLAN/TODO。

  1. 01

    从工具集合到 Package Identity

    Trigger
    模块数量增长后，目录和 README 无法稳定表达依赖。
    Change
    统一 package、asmdef、Catalog 与 layer 身份。
    Evidence
    Inventory 与 architecture verifier 提供机器可读结构事实。
    Limitation
    结构存在不等于生命周期成熟。
  2. 02

    从默认全局生命周期到显式 Scope

    Trigger
    重复初始化、场景切换和异步退出暴露隐式 Owner。
    Change
    引入 composition root、Scope ownership、startup rollback 与 async exit。
    Evidence
    Runtime Foundation local 与 same-SHA Runner 证据。
    Limitation
    Runner 不替代 Release 或 Production。
  3. 03

    从 Unity-only 到 Portable Core

    Trigger
    配置、存档、输入和工具语义需要进入不同宿主。
    Change
    Core 保持 no-engine，平台能力进入 Unity / Godot Adapter。
    Evidence
    Core identity、capability matrix 与专项 Adapter 本地验证。
    Limitation
    Godot 只按已证明能力展示，不声明整体对等。
  4. 04

    从单一范式到 Progressive Cost

    Trigger
    统一 UI 架构在简单和复杂页面上都产生不匹配成本。
    Change
    Direct、Binding、MVVM、Structured 形成渐进选择。
    Evidence
    多路径本地回归和 Consumer 映射。
    Limitation
    UI Runner 仍 pending，真实视觉素材有限。
  5. 05

    从自证到 Independent Consumer

    Trigger
    Framework 自测无法证明真实项目采用和清理路径。
    Change
    固定 Consumer / Framework 双方提交、包哈希与验证范围。
    Evidence
    七个 reviewed consumer snapshots。
    Limitation
    固定快照不会自动证明当前 main 或 Production。
  6. 06

    从项目页到 Engineering Evidence

    Trigger
    模块目录无法解释 Ownership、Trade-off 与证据边界。
    Change
    建立首页 3 分钟路径、Engineering Hub、领域深页、案例和 Evidence Ladder。
    Evidence
    生成式站点合同、测试、幂等与浏览器验证。
    Limitation
    本地网站完成不等于远端 Runner 或 Pages publication。
