工作事项

切换列表、表格或看板，按项目、状态、类型和优先级筛选。打开事项可查看目标、附件和验收标准。

截图使用演示项目数据。点击可查看原图。

执行请求

在事项里新建执行请求，选择仓库并填写目标。截图中的请求正在等待授权。

请求获准后，配置的 Desktop Worker 领取任务并回报进度。

交付验收

打开具体交付版本，查看结果、附件与证据，再按项目设置进行本人验收或独立审查。

接入与权限

  • Web 使用账户登录，打开有权限的项目。
  • MCP 按项目授权后查询事项和证据，或创建事项草稿。
  • Desktop Worker 配置桌面节点，审核并授权后才能启动执行。
能力与执行规则
Collaboration Domain
Work、Attempt、Delivery、附件与审计的统一领域合同。
Web Workbench
项目、事项、待处理、执行与交付的统一工作台。
Research Artifact & Proposal Ingress
把研究材料或受限 QQ 提案信封固化为不可变 Artifact 和待审批 Proposal，不自动批准、不自动改写目标仓库。
Agent Execution Contract
连接授权、上下文、Runner 权限与 AgentRun 状态，保留 claim、lease、恢复和只读检查。
读取事实
从显式登记的 Git 与 Gitea 来源核对事实，来源身份与业务状态分别记录。
显式授权
Research Artifact 只生成 pending-approval 提案；WorkAuthorization 明确限定目标、权限与执行边界。
受限执行
TaskEnvelope 与 Runner 权限求交集，AgentRun 通过 claim、lease、heartbeat 与 recovery 管理生命周期。
验证与审计
把结果、失败、边界与后续入口分开记录；未知终态不盲目重试，未取得证据就不升级结论。
