源仓更新 · 2026-08-29

WHY IRIS ENGINEERING

把研发事实、显式授权与验证边界组织成可复查的工作流

Iris Engineering 不替代 Git、Gitea、Sakura Framework 或人的判断。它负责把分散事实变成只读视图，把研究建议变成待审批提案，再让获得授权的任务拥有明确目标、权限和恢复边界。

OBSERVE · AUTHORIZE · EXECUTE · VERIFY

从事实到验证，四段互不越权

  1. 01

    Observe

    读取事实

    从 Git、Gitea Adapter、本地 Snapshot 与只读报告收集事实，不复制第二套可独立修改的业务真理源。
  2. 02

    Authorize

    显式授权

    Research Artifact 只生成 pending-approval 提案；WorkAuthorization 明确限定目标、权限与执行边界。
  3. 03

    Execute

    受限执行

    TaskEnvelope 与 Runner 权限求交集，AgentRun 通过 claim、lease、heartbeat 与 recovery 管理生命周期。
  4. 04

    Verify

    验证与审计

    把结果、失败、边界与后续入口分开记录；未知终态不盲目重试，未取得证据就不升级结论。

P1–P10 PRODUCT BASELINE

四个已经形成合同的能力层

从 Workflow Core 到只读视图，再到 Research Artifact 与 Agent Execution，公开展示只描述已实现的本地产品边界。

01 / WORKFLOW-CORE

Workflow Core

版本化合同、状态与 Flag 规则、幂等 Inbox、Preview、Reconciliation 和 Audit。

  • Closed JSON Schema
  • Deterministic plan
  • Inbox & reconciliation

02 / READ-MODELS

Read Models & Dashboard

Today、Milestone、Quality、Build 与 Operations 的只读投影，固定本地回环、GET/HEAD-only。

  • Today / Milestone
  • Quality / Build
  • Operations health

03 / RESEARCH-INTAKE

Research Artifact & Proposal Ingress

把研究材料或受限 QQ 提案信封固化为不可变 Artifact 和待审批 Proposal，不自动批准、不自动改写目标仓库。

  • Immutable artifact
  • QQ Research Proposal Ingress
  • Pending proposal

04 / AGENT-EXECUTION

Agent Execution Contract

连接授权、上下文、Runner 权限与 AgentRun 状态，保留 claim、lease、恢复和只读检查。

  • Task envelope
  • Permission intersection
  • Claim / lease / recovery

EVIDENCE BEFORE CLAIMS

通过与失败都保留原本含义

本地合同、只读行动视图与外部试点分别陈述；传输失败没有被重试或改写成接入成功。

本地通过本地产品基线

Workflow、Persistence、CLI、Dashboard、Research Intake 与 Agent Execution 均有本地合同和回归覆盖。

本地通过只读行动视图

Today、Milestone、Quality、Build 与 Operations 页面保持零凭据、零远端写入和输入故障隔离。

本地通过QQ 研究提案入口

P9.1 只把受限提案映射为不可变 Artifact 与 pending-approval Proposal；本地合同已交付，真实 ingress 尚未执行。

失败关闭Canonical external read

试点在首个传输请求失败后停止，未重试、未取得远端事实，也没有把失败解释成接入成功。

CURRENT BOUNDARIES

当前边界

失败关闭不是保守文案，而是产品设计的一部分：没有新的授权与证据，就不扩大能力结论。

  • Iris Engineering 不拥有 Unity Runtime、玩法逻辑或 Sakura Framework 的包与发布状态。
  • 真实平台读取、写入、Runner、工作树与外部 Agent 接入都必须单独授权。
  • P9.1 QQ 提案入口只能创建 pending-approval Proposal，不能批准任务、创建执行合同或改写目标仓库。
  • Dashboard 是可丢弃、可重建的 Read Model，不成为新的 Issue、PR 或 CI 真理源。
  • P6.1 与 P7 的当前跨平台证据来自 Windows host；macOS 与 Linux 仍需在相同变更上分别验证。
