1. 文档定位

本期新增的宏观游戏类型为：

塔防游戏。

常见名称包括：

  • Tower Defense；

  • TD；

  • 路径防守游戏；

  • 阵地防御游戏；

  • 波次防守策略游戏。

本文讨论的不是动作游戏中的单次守点任务，也不是RTS中的静态炮塔模块，而是一种足以独立支撑完整游戏的宏观品类。

塔防游戏最具代表性的设计范式可以概括为：

将敌人的推进建模为一股沿空间拓扑持续流动的压力，玩家通过有限经济在关键位置部署、升级和重组防御节点，使攻击范围、目标选择、控制效果、伤害类型和路径结构共同形成防线；每个波次既是对当前防御体系的压力测试，也是下一轮资源分配的输入，从而形成“读取威胁—空间布防—波次执行—漏洞暴露—经济再投资”的循环。

塔防游戏的核心并不是“塔自动攻击敌人”，而是持续处理以下问题：

  • 敌人将从哪里出现；

  • 会沿哪些路线推进；

  • 哪些位置能够覆盖更长路径；

  • 当前缺少单体伤害、群体伤害还是控制；

  • 资源应当用于新建防御还是升级旧塔；

  • 是否需要为后续波次保留资金；

  • 不同塔之间能否形成协同；

  • 敌人如何突破当前防线；

  • 玩家如何快速定位防线失效的原因；

  • 关卡如何在不依赖纯数值膨胀的前提下持续增加压力。

2. 类型定义

塔防游戏，是以敌人波次、路径推进、空间部署、自动战斗、资源再投资和防线完整性为核心的策略游戏类型。

其典型循环为：

  1. 玩家查看地图、路线和下一波敌人信息；

  2. 使用初始资源建造防御塔、陷阱、阻挡物或支援设施；

  3. 启动敌人波次；

  4. 敌人沿路径向核心、基地或出口移动；

  5. 防御单位依据射程、目标优先级和攻击规则自动行动；

  6. 敌人死亡后提供资源、能量或其他收益；

  7. 漏过的敌人削减基地生命、增加污染或达成敌方目标；

  8. 玩家在波次间或战斗中建造、升级、出售和重组防线；

  9. 新敌人逐步引入护甲、飞行、分裂、隐身、治疗和Boss机制；

  10. 玩家调整伤害类型、控制链和空间覆盖；

  11. 击败最终波次或Boss后完成关卡；

  12. 获得局外解锁、评分、科技或新的防御单位；

  13. 在新地图和新规则下重新构建防御体系。

塔防游戏中的主要资源通常包括：

  • 建造货币；

  • 波次奖励；

  • 基地生命；

  • 建造格；

  • 防御塔数量上限；

  • 塔位覆盖面积；

  • 主动技能能量；

  • 升级材料；

  • 波次准备时间；

  • 敌人路径信息；

  • 临时增益；

  • 局外科技点。

其中最重要的隐性资源是：

有效路径覆盖时间，即防御系统能够对敌人持续输出、控制和重新锁定的总时间。

3. 核心设计范式

塔防游戏最具代表性的设计范式由八个核心支柱构成。

3.1 敌人是沿空间拓扑移动的压力流

敌人不是普通战斗单位的简单集合，而是一股持续经过防区的动态流量。

防守系统需要处理：

  • 敌人出现频率；

  • 路径长度；

  • 速度差异；

  • 敌人密度；

  • 单位体积；

  • 编队间隔；

  • 路线分叉；

  • 不同路线的到达时间；

  • 特殊敌人对队伍结构的影响。

因此，塔防中的敌人强度不能只看单个单位属性，还需要看：

  • 单位数量；

  • 时间密度；

  • 阵型；

  • 重叠程度；

  • 能否使防御塔反复切换目标；

  • 是否突破控制和群伤能力的处理上限。

3.2 防御塔的价值高度依赖位置

同一座塔放置在不同位置，实际价值可能存在巨大差异。

位置会影响：

  • 路径覆盖长度；

  • 能够同时覆盖的路线数量；

  • 敌人首次进入射程的时间；

  • 敌人离开射程的时间；

  • 与减速、聚怪和阻挡设施的组合；

  • 是否能攻击飞行单位；

  • 是否容易被敌人攻击或干扰；

  • 是否占用关键地形。

塔的强弱不能脱离：

  • 地图拓扑；

  • 建造格；

  • 射程形状；

  • 路径曲率；

  • 视线；

  • 高低差；

单独评价。

3.3 建造、升级和出售构成资源机会成本

玩家拥有有限资源，需要在以下选择间权衡：

  • 增加一座新塔；

  • 升级已有核心塔；

  • 建造低级补漏塔；

  • 购买控制能力；

  • 保留资源应对未知波次；

  • 出售错误部署并承担损失；

  • 投资长期经济设施。

新建防御通常增加：

  • 覆盖范围；

  • 目标数量；

  • 战线冗余；

  • 多路线适应能力。

升级已有塔通常增加：

  • 单点强度；

  • 技能效果；

  • 射程或伤害；

  • 特殊机制；

  • 单位空间效率。

二者不能存在无条件最优选项。

3.4 自动攻击不等于没有战术控制

防御塔可以自动攻击，但玩家仍应通过以下内容影响结果：

  • 建造位置；

  • 塔型组合；

  • 升级路线；

  • 目标优先级；

  • 主动技能；

  • 阻挡和路径改变；

  • 卖塔重建；

  • 波次提前启动；

  • 英雄移动；

  • 临时增益分配。

玩家主要进行的是：

战斗前的系统设计与战斗中的局部干预。

3.5 每个波次都是一次结构性压力测试

波次不应只是敌人生命和数量持续增加。

不同波次可以测试：

  • 单体持续输出；

  • 群体伤害；

  • 快速目标；

  • 高护甲目标；

  • 魔法抗性；

  • 飞行单位；

  • 隐身单位；

  • 分裂单位；

  • 治疗和增益单位；

  • 多路线同时推进；

  • Boss和小怪混合；

  • 长时间持续压力。

玩家失败时，应能够判断：

  • 当前防线缺少什么；

  • 哪一段路径发生拥堵；

  • 哪种敌人突破；

  • 是伤害不足、控制不足还是目标选择错误。

3.6 塔之间的组合价值应高于单塔数值叠加

高质量塔防通常依赖防御协同。

常见协同包括：

减速 → 延长敌人在射程内的时间 → 提高持续伤害塔总输出

聚怪 → 增加敌人重叠 → 提高范围伤害效率

破甲 → 降低敌方防御 → 提高高攻速塔收益

标记 → 提高对特定目标的伤害 → 帮助单体塔处理精英

阻挡 → 将敌人集中在固定区域 → 形成火力杀伤区

经济设施 → 降低短期战力 → 提高后续波次投资能力

塔的价值应部分来自其在体系中的角色，而不是只比较每秒伤害。

3.7 敌人需要突破防御体系，而不是只吸收伤害

敌人可以通过以下方式挑战玩家：

  • 高速移动；

  • 护甲；

  • 魔抗；

  • 飞行；

  • 隐身；

  • 分裂；

  • 复活；

  • 治疗；

  • 召唤；

  • 护盾；

  • 暂时无敌；

  • 干扰塔；

  • 改变路径；

  • 传送；

  • 偷取资源；

  • 击毁阻挡设施。

敌人机制应针对防御结构的不同薄弱点，而不是单纯提高生命值。

3.8 波次间经济将局部战斗连接为长期防线演化

每一波的结果会影响：

  • 可用资金；

  • 基地剩余生命；

  • 可获得的评分；

  • 下一波准备能力；

  • 是否能提前投资高级塔；

  • 是否需要修复防线；

  • 是否有资格挑战额外波次。

因此，玩家并不是每波重新开始，而是在维护一套持续演化的防御系统。

4. 与相近类型的边界

4.1 与即时战略游戏的区别

即时战略通常强调：

  • 单位生产；

  • 资源采集；

  • 基地扩张；

  • 主动控制军队；

  • 多方向进攻。

塔防更强调：

  • 敌方沿路径主动推进；

  • 防御单位多数自动行动；

  • 空间部署；

  • 波次压力；

  • 阵地和火力覆盖。

4.2 与自动战斗游戏的区别

自动战斗游戏通常强调：

  • 阵容；

  • 单位购买；

  • 随机商店；

  • 站位；

  • 回合对战。

塔防更强调：

  • 地图路径；

  • 射程覆盖；

  • 连续敌人流；

  • 建造位置；

  • 波次节奏；

  • 基地防守。

4.3 与生存建造防守的区别

生存建造防守通常还包括：

  • 开放世界采集；

  • 基地建设；

  • 长周期生产；

  • 角色生存需求；

  • 昼夜循环。

塔防的核心更加集中于：

  • 路径；

  • 波次；

  • 防御节点；

  • 资源循环；

  • 自动战斗。

4.4 与固定炮塔射击游戏的区别

固定炮塔射击主要依赖玩家直接瞄准和射击。

塔防中的玩家重点是：

  • 防线设计；

  • 塔型组合；

  • 资源投资；

  • 路线覆盖；

  • 自动目标规则。

4.5 与工厂自动化游戏的区别

工厂自动化处理确定性生产物流。

塔防虽然也存在流量和吞吐概念，但其流动对象是：

  • 具有生命；

  • 速度；

  • 抗性；

  • 行为；

  • 技能；

的敌人，并且系统目标是阻止其通过，而非提高物料产出。

5. 总体运行时架构

推荐将运行时划分为以下十六个核心域：

  1. 关卡与地图拓扑域；

  2. 路径、导航和路线变更域；

  3. 波次定义与生成调度域；

  4. 敌人单位与推进域；

  5. 防御塔建造与占位域；

  6. 塔目标搜索与攻击调度域；

  7. 投射物、命中与伤害域；

  8. 控制、状态与抗性域；

  9. 阻挡、陷阱与路径交互域；

  10. 资源、奖励与经济域；

  11. 升级、分支与出售域；

  12. 主动技能、英雄和支援域；

  13. 基地生命、漏怪和关卡结算域；

  14. 局外科技、解锁与战役域；

  15. 存档、回放和确定性域；

  16. 调试、内容验证和平衡分析域。

总体运行流程如下：

加载关卡定义 → 构建路径图和建造区域 → 初始化基地生命与玩家资源 → 玩家部署初始防御 → 波次调度器创建生成计划 → 敌人按时间和路线进入地图 → 防御塔搜索目标并创建攻击行为 → 投射物和效果系统执行伤害与控制 → 敌人死亡产生奖励 → 漏过敌人削减基地状态 → 波次完成后进入整备 → 玩家建造、升级、出售和调整优先级 → 下一波提高压力或改变敌人结构 → 最终Boss或最后波次完成 → 生成关卡结果 → 更新局外进度和评分

6.2 固定步长职责

以下系统建议使用固定步长：

  • 敌人移动；

  • 塔攻击冷却；

  • 投射物；

  • 状态持续时间；

  • 周期伤害；

  • 波次生成；

  • 阻挡；

  • 主动技能；

  • Boss阶段。

6.3 时间倍率

通常支持：

  • 暂停；

  • 正常速度；

  • 二倍速；

  • 更高倍速。

改变时间倍率不能改变：

  • 攻击次数；

  • 波次生成；

  • 状态持续；

  • 敌人到达顺序；

  • 随机结果；

  • 最终伤害。

6.4 波次准备阶段

准备阶段可以支持：

  • 自由建造；

  • 有限倒计时；

  • 手动提前开始；

  • 查看敌人预告；

  • 调整目标优先级；

  • 使用预部署技能。

提前开始可以奖励：

  • 额外货币；

  • 能量；

  • 评分；

  • 连胜倍率。

7.6 多路线地图

多路线可以形成：

  • 同时防守；

  • 共享火力点；

  • 路线优先级；

  • 资源分散；

  • 跨路线塔位；

  • 路线切换。

关键塔位通常是能够：

  • 覆盖多个入口；

  • 覆盖路径回环；

  • 配合阻挡；

  • 提供长时间射程；

的位置。

7.7 动态路径

关卡中可以出现：

  • 门开启；

  • 桥梁断裂；

  • 路线分流；

  • Boss破坏地形；

  • 玩家设置路障；

  • 环境机关改变道路。

任何路径变化都必须重新验证：

  • 所有敌人仍有合法目标路径；

  • 不会生成导航死锁；

  • 已在路径中的敌人可以迁移；

  • 路径缓存正确失效；

  • 玩家无法完全永久封死所有路线，除非规则允许。

  • 当前目标死亡后切换；

  • 新目标威胁高于阈值时切换；

  • 蓄力攻击期间不切换。

13.5 过度集火

如果所有单体塔同时攻击一个即将死亡的敌人，可能浪费大量伤害。

可以选择：

  • 不进行协调，保留传统塔防特征；

  • 预估投射物伤害；

  • 降低已被覆盖目标评分；

  • 仅让智能塔进行伤害预留。

协调程度越高，系统越高效，但也可能削弱玩家对塔位和攻速的判断。

27. 完整事件与执行流程示例

以下以“玩家面对包含护甲先锋、治疗单位和高速小怪的双路线波次”为例。

27.1 波次预告

系统显示：

  • 左路出现重甲先锋；

  • 右路出现高速小怪；

  • 两路中后段会出现治疗单位；

  • 波次总持续时间较长。

27.2 玩家评估防线

当前防线：

  • 左路有单体物理塔；

  • 中央交叉点有范围法术塔；

  • 右路只有低级速射塔；

  • 缺少稳定控制；

  • 资源不足以同时升级两路。

27.3 波前调整

玩家选择：

  • 在中央交叉点建造减速塔；

  • 保留部分资源；

  • 不升级左路物理塔；

  • 将范围法术塔目标策略改为“敌人密度最高”。

27.4 波次开始

重甲先锋沿左路推进。

物理塔伤害受到护甲压制，但减速延长其停留时间。

范围法术塔能够攻击左路转弯段。

27.5 高速单位进入右路

高速小怪迅速穿过低级速射塔射程。

进入中央交叉点后被减速。

两路敌人在中央区域形成短暂重叠。

27.6 治疗单位出现

治疗单位位于敌群后方。

当前目标策略使部分塔持续攻击前排先锋，治疗单位开始恢复敌群。

玩家发现：

  • 伤害总量并非完全不足；

  • 主要问题是治疗目标没有被优先击杀。

27.7 战斗中干预

玩家：

  1. 将单体塔改为“优先支援单位”；

  2. 使用一次区域冻结；

  3. 快速建造一座低级魔法塔补充左路破甲不足；

  4. 暂不升级减速塔。

27.8 防线稳定

治疗单位被优先击杀。

失去治疗后，重甲先锋在中央杀伤区被消灭。

右路高速小怪因减速和冻结未能突破。

27.9 波次结算

系统记录：

  • 无漏怪；

  • 冻结技能已进入冷却；

  • 新魔法塔造成有效补充；

  • 单体塔目标切换显著提高成功率；

  • 玩家获得波次奖励和提前开波奖励。

27.10 下一轮决策

下一波预告包含飞行单位。

玩家需要决定：

  • 建造专门防空塔；

  • 升级现有速射塔获得对空能力；

  • 依赖主动技能临时处理；

  • 出售左路临时魔法塔回收资源。

完整循环体现：

威胁预告 → 防线评估 → 资源投资 → 自动战斗 → 漏洞识别 → 战斗中调整 → 波次结算 → 面向新威胁重组

30. 失败隔离

30.1 建造事务失败

如果建造过程中发现：

  • 资源不足；

  • 位置冲突；

  • 地图版本变化；

  • 塔定义缺失；

则：

  • 不扣除资源；

  • 不保留占位；

  • 不创建半完成塔；

  • 返回明确失败原因；

  • 允许玩家立即重新操作。

30.2 目标搜索失败

塔无法找到合法目标时：

  • 保持待机；

  • 清理已失效目标；

  • 下一搜索周期重新查询；

  • 记录射程、标签和视线过滤过程；

  • 不让塔进入永久锁死。

30.3 投射物目标失效

目标死亡或离开世界时：

  • 按投射物策略销毁、重定向或命中原位置；

  • 释放目标引用；

  • 不重复结算伤害；

  • 记录原目标和处理策略。

30.4 敌人导航失败

敌人无法继续前进时：

  1. 检查当前路径是否失效；

  2. 请求最近合法路径；

  3. 尝试迁移到最近路径节点；

  4. 临时禁用碰撞以解除局部重叠；

  5. 超时后安全移除并按规则处理；

  6. 记录地图、阻挡和敌人状态。

不能直接将敌人传送到终点。

30.5 波次无法结束

定期检测：

  • 未生成敌人计数；

  • 场上敌人；

  • 待分裂敌人；

  • 待召唤敌人；

  • 已失效但未清理实体；

  • Boss阶段任务。

异常实体可以：

  • 重建；

  • 安全清理；

  • 标记为无奖励移除；

  • 保留审计记录。

30.6 升级失败

升级事务必须：

  • 同时更新资源、升级节点和派生属性；

  • 任一失败时整体回滚；

  • 不出现已扣钱但塔未升级；

  • 不出现表现升级但逻辑仍是旧塔。

30.7 状态触发递归

状态组合导致无限触发时：

  • 使用显式触发队列；

  • 限制最大深度；

  • 限制同一根事件的重复次数；

  • 中止后续异常触发；

  • 保留此前合法结果；

  • 输出完整触发链。

30.8 关卡结算异常

关卡已经完成但奖励提交失败时：

  • 保存LevelResultSnapshot；

  • 不重复发放奖励；

  • 不要求玩家重新完成关卡；

  • 使用幂等结果ID重试；

  • 将结果标记为PendingCommit。

33.1 空间索引

用于加速：

  • 光环；

  • 控制区域；

  • 敌人密度；

  • 投射物碰撞。

33.2 目标搜索分频

不同塔无需每Tick搜索目标。

  • 攻击间隔；

  • 当前目标状态；

  • 塔类型；

  • 敌人进入和离开事件；

目标优先级可以直接读取标准化PathProgress，而不必频繁计算到终点的完整路径距离。

关键投射物

  • 简化转向；

  • 聚合部分状态更新；

  • 降低远端动画频率。

33.6 范围伤害批处理

对同一区域的周期伤害可以：

  • 批量查询敌人；

  • 统一计算公共修正；

  • 分别提交结果；

  • 合并表现。

  • 尸体；

  • 投射物表现；

36. 玩家体验设计

36.1 下一波威胁必须可读

预告可以展示：

  • 敌人类型；

  • 路线；

  • 数量级；

  • 飞行；

  • 护甲；

  • 特殊能力；

  • Boss。

不一定显示精确数量，但应支持合理准备。

36.2 玩家必须知道敌人为什么漏过

失败反馈应说明：

  • 哪条路线；

  • 哪种敌人；

  • 当时速度；

  • 是否隐身；

  • 哪些塔未攻击；

  • 是否缺少防空；

  • 是否被Boss干扰；

  • 当前伤害是否被护甲克制。

36.3 塔位价值需要可视化

建造前应显示：

  • 射程；

  • 路径覆盖；

  • 目标类型；

  • 预计受益路线；

  • 地形影响；

  • 光环；

  • 阻挡关系。

36.4 塔的职责必须容易理解

玩家应快速判断：

  • 单体；

  • 群伤；

  • 控制；

  • 破甲；

  • 防空；

  • 侦测；

  • 经济；

  • 支援。

36.5 升级分支要表达玩法变化

升级界面应明确：

  • 伤害类型；

  • 目标数量；

  • 攻击方式；

  • 新状态；

  • 职责变化；

  • 对哪些敌人有效。

36.6 战斗中信息不能过载

高密度战斗中应优先显示：

  • 漏怪风险；

  • Boss技能；

  • 塔失效；

  • 基地受损；

  • 主动技能状态；

  • 新敌人能力。

普通伤害数字可以合并或关闭。

36.7 倍速不应降低可操作性

在高倍速下：

  • 警报需要提前；

  • 玩家应能快速暂停；

  • 建造和技能操作应可靠；

  • Boss阶段转换应提供提示。

36.8 实验成本要合理

玩家需要通过：

  • 出售返还；

  • 关卡重试；

  • 塔信息预览；

  • 沙盒测试；

  • 低成本早期关卡；

学习防御组合。

37. 常见设计失败

37.1 塔只按DPS排序

低DPS的控制、支援和破甲塔没有独立价值。

37.2 地图塔位差异不明显

所有位置的覆盖和收益近似，空间决策失去意义。

37.3 波次只增加生命和数量

没有引入新的结构性压力。

37.4 敌人特殊能力没有预告

玩家在波次开始后才发现需要防空、侦测或魔法伤害。

37.5 Boss完全免疫控制和状态

控制、减益和辅助塔在最终挑战中全部失效。

37.6 出售返还过高

玩家可以无成本随时重构，不需要承担部署决策。

37.7 出售返还过低

玩家一旦放错塔位就只能重开。

37.8 所有塔自动选择相同目标

造成严重过量伤害和大量漏怪，但玩家无法调整。

37.9 路径修改没有可达性验证

玩家封死道路后敌人卡住或停止波次。

37.10 支援塔无条件叠加

形成固定光环堆叠中心，其他塔位失去价值。

37.11 战斗倍速改变结算结果

不同速度下出现攻击次数、控制时间或波次生成差异。

37.12 波次完成依赖场上对象数量

隐藏、失效或未清理实体导致关卡永久无法继续。

37.13 防线崩溃缺乏原因解释

玩家只看到基地突然大量掉血，不知道哪种敌人突破。

37.14 局外数值成长覆盖关卡策略

玩家只靠永久加成通关，不再需要理解塔位和组合。

38. 最小可行原型

一个能够验证塔防核心范式的最小原型可以包含：

地图

  • 3张正式地图；

  • 1张单路线教学图；

  • 1张双路线交叉图；

  • 1张动态路径图；

  • 6至10个有明显差异的塔位；

  • 1个基地目标。

防御塔

  • 单体物理塔；

  • 群体魔法塔；

  • 高频防空塔；

  • 减速塔；

  • 破甲支援塔；

  • 阻挡单位；

  • 1种主动技能。

敌人

  • 基础单位；

  • 高速单位；

  • 重甲单位；

  • 群体小怪；

  • 飞行单位；

  • 治疗单位；

  • 分裂单位；

  • 1个Boss。

波次

  • 每关10至15波；

  • 包含教学波、组合波、精英波和Boss波；

  • 支持波次预告和提前开波。

经济

  • 初始资源；

  • 击杀奖励；

  • 波次奖励；

  • 建造；

  • 升级；

  • 出售；

  • 提前开波奖励。

必要基础设施

  • PathGraph；

  • WaveDefinition；

  • SpawnGroupDefinition；

  • EnemyRuntimeState；

  • TowerRuntimeState；

  • TargetingProfile；

  • AttackProfile；

  • ProjectileState；

  • StatusState；

  • EconomyState；

  • GoalState；

  • LevelResultSnapshot。

必要调试工具

  • 路径图查看器；

  • 塔覆盖分析器；

  • 目标选择检查器；

  • 伤害解释器；

  • 波次时间线；

  • 防线吞吐分析器；

  • 经济时间线；

  • 关卡回放。

该原型应重点验证：

  • 不同塔位是否具有明显空间价值；

  • 新建与升级是否形成真实取舍；

  • 单体、群伤、控制和防空是否分别有使用场景；

  • 波次是否测试不同防线能力；

  • 目标优先级是否能够影响结果；

  • 倍速是否保持相同逻辑结果；

  • 动态路径是否不会导致敌人卡死；

  • 控制组合是否不会形成永久锁定；

  • 玩家是否能解释每次漏怪原因；

  • 同一命令和随机种子是否能够重现完整关卡。

39. 推荐实施顺序

第一阶段：固定步长模拟、地图和PathGraph 第二阶段：敌人生成、路径移动和基地漏怪 第三阶段：建造区域、塔实例和基础攻击 第四阶段：目标搜索、投射物和伤害 第五阶段：波次调度、奖励和经济 第六阶段：升级、出售和目标优先级 第七阶段：范围伤害、状态和控制 第八阶段：飞行、隐身、治疗和特殊敌人 第九阶段：阻挡、陷阱和支援光环 第十阶段：Boss、主动技能和动态路径 第十一阶段：局外解锁、评分和战役 第十二阶段：回放、自动模拟和内容验证

不建议在以下基础设施尚未稳定时先制作大量塔和敌人：

  • PathGraph；

  • 目标搜索；

  • 攻击调度；

  • 伤害顺序；

  • 状态队列；

  • 波次完成条件；

  • 经济守恒；

  • 确定性回放。

40. 架构验收标准

系统初步成立时，应满足：

  • 敌人通过独立PathGraph向目标推进；

  • 地面、飞行和特殊路线具有明确规则；

  • 所有出生点均存在合法目标路径；

  • 建造命令使用空间、资源和版本验证；

  • 建造、升级和出售采用原子事务；

  • 防御塔通过统一目标搜索系统获得目标；

  • 目标选择支持多种可配置优先级；

  • 攻击、投射物、伤害和状态相互分离；

  • 相同塔在不同位置能产生明显不同覆盖价值；

  • 新建塔和升级旧塔不存在全局唯一最优解；

  • 单体、群体、控制、支援和防空均具有独立职责；

  • 敌人特殊能力能够针对不同防线薄弱点；

  • Boss不会完全使整类防御塔失效；

  • 波次完成不依赖不可靠的场景对象计数；

  • 控制系统具有递减、免疫或覆盖限制；

  • 倍速不会改变攻击次数、状态时间和最终结果；

  • 动态路径改变后会重新进行可达性验证；

  • 关卡结果和局外奖励具有幂等性；

  • 调试工具能够解释某座塔为什么没有攻击；

  • 调试工具能够解释某种敌人为什么突破防线；

  • 新塔和新敌人通常不需要修改关卡主循环；

  • 同一随机种子和玩家命令能够确定性回放关卡。

41. 可迁移到其他游戏的设计思想

41.1 空间覆盖时间比静态射程更能表达设施价值

可迁移到：

  • 战术游戏；

  • 安防系统；

  • 雷达；

  • 支援技能；

  • 区域控制。

一个设施的价值不仅取决于覆盖面积，也取决于目标会在覆盖区停留多久。

41.2 流量、密度与吞吐共同决定系统压力

可迁移到：

  • 工厂；

  • 交通；

  • 网络服务；

  • 敌群战斗；

  • 队列系统。

单个对象强度不足以表达系统负载，还需要考虑单位到达频率和并发数量。

41.3 自动系统仍需要允许玩家控制策略参数

可迁移到：

  • 自动战斗；

  • AI队友；

  • 生产系统；

  • 防御设施；

  • 工作调度。

玩家不必逐次控制动作，但应能调整：

  • 目标；

  • 优先级；

  • 策略；

  • 资源；

  • 位置。

41.4 波次是渐进式压力测试框架

可迁移到：

  • 生存模式；

  • 教学；

  • 性能测试；

  • 竞技挑战；

  • Boss Rush。

每一波可以针对系统的不同维度进行测试，而不是只线性提高数值。

41.5 新建与升级是广度和深度投资的通用取舍

可迁移到：

  • 城市建设；

  • 工厂；

  • 技能树；

  • 军队；

  • 基地经营。

新建提高覆盖和冗余，升级提高单位空间效率和专业强度。

41.6 支援能力的价值来自改变其他模块效率

可迁移到：

  • 团队RPG；

  • 卡牌；

  • RTS；

  • 自动战斗；

  • MMO职业。

辅助单位不必直接产生高伤害，其价值可以通过被增强对象的增量表现。

41.7 目标优先级是连接自动执行与玩家意图的接口

可迁移到：

  • 防御系统；

  • 生产调度；

  • 单位战术。

系统自动执行动作，但优先级由玩家或策略层定义。

41.8 动态路径变化必须伴随可达性验证

  • 城市交通；

任何封路、开路和传送变化都需要检查核心目标仍然可达。

41.9 失败解释器是复杂策略系统的重要组成部分

  • 上游原因是什么；

  • 可通过什么策略修复。

41.10 波次间结算可以连接短期执行和长期演化

  • 经营周期。

每个阶段的结果既结束当前压力，也为下一阶段提供资源和状态输入。

42. 本次防重记录

新增宏观游戏类型

塔防游戏。

常见名称：

  • Tower Defense；

  • TD；

  • 路径防守游戏；

  • 阵地防御游戏；

  • 波次防守策略游戏。

核心范式

将敌人的推进建模为沿路径拓扑持续流动的压力，玩家使用有限经济在关键空间位置部署、升级、出售和重组防御节点，使射程覆盖、目标优先级、伤害类型、控制效果、阻挡能力和支援光环共同形成防线；每个波次对当前防御体系的不同维度进行压力测试，并通过击杀收益、基地损失和波次奖励驱动下一轮投资，形成“威胁预告—空间布防—自动执行—漏洞识别—经济再投资”的长期循环。

核心识别特征

  • 敌人按波次从出生点向目标点推进；

  • 地图路径和塔位共同决定防御价值；

  • 防御塔多数自动搜索和攻击目标；

  • 玩家主要控制位置、塔型、升级和优先级；

  • 新建防御与升级旧塔形成广度和深度投资取舍；

  • 波次通过敌人密度、路线和能力测试不同防线维度；

  • 单体、群伤、控制、支援、防空和阻挡具有独立职责；

  • 塔之间通过减速、聚怪、破甲、标记和光环形成协同；

  • 敌人通过飞行、隐身、护甲、治疗、分裂和Boss技能突破防线；

  • 敌人死亡提供资源，漏怪损害基地或关卡目标；

  • 波次间结算推动防线持续演化；

  • 目标优先级连接自动战斗与玩家战术意图；

  • 动态路径必须经过可达性验证；

  • 倍速不能改变逻辑结果；

  • 调试系统需要解释塔为什么未攻击以及敌人为什么漏过。
