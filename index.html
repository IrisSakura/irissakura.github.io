ENGINEERING CASES

三个具体问题，三组可检查决策

01 · COMBAT

统一技能、潜能与祝福的能力入口

问题
多条成长路径如何作用于同一战斗事实？
约束
效果必须可组合，伤害提交不能出现双重事实。
决策
使用标签、属性、效果和能力入口组织结算。
结果
实时战斗与构筑系统在同一运行循环中协作。
02 · SAVE

通过房间快照维持 Run 连续性

问题
跨房间推进时如何恢复局内状态？
约束
场景对象不能成为持久化事实源。
决策
在明确推进节点提交结构化 Run 快照。
结果
房间分支、成长选择和恢复路径拥有清晰边界。
03 · LOCAL LLM

让本地模型参与玩法而不破坏运行循环

问题
生成式祝福怎样转化为可执行游戏效果？
约束
输出不稳定、调用可能失败，不能阻断游戏。
决策
采用结构化输出、白名单映射与失败回退。
结果
生成内容进入可验证的祝福选择与效果执行。
