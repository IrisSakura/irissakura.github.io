# 个人网站日常实施流程

本页用于维护站点源码、内容和生成链。公开页面面向访客，工程记录留在仓库；批准的视觉方向、GitHub SSH 身份和授权边界见[根规范](../../AGENTS.md)。

## 实施标准与入口

| 范围 | 可编辑来源与权威入口 |
| --- | --- |
| 页面和导航 | `scripts/generate-site.mjs` 及其模板 Owner；[根 README](../../README.md)说明内容来源和构建链。生成 HTML 由 Owner 刷新 |
| 视觉、布局与控件 | [美学合同](../brand/interface-aesthetic-contract.md)、[组件所有权](../ui-components.md)；共享几何在 token，共享控件在 interface 层，页面拥有构图 |
| 动态、项目与作品内容 | README 的 Living 维护说明、[项目状态同步](project-status-sync.md)、[项目展示](project-showcases.md)；更新登记来源和经过审阅的真实材料 |
| 外部项目公开投影 | [Journal](journal-sync.md)、[Iris Engineering](iris-engineering-sync.md)、[Framework](framework-sync.md)等既有 importer；保持固定来源、身份校验、脱敏和生成归属 |

相关维护先查[开发问题备忘录](development-memo.md)。当前入口和 manifest 优先于旧视觉实验、旧路径和历史验收数字。

## 一次维护的顺序

1. **确认用户结果和基线。** 检查 HEAD、staged、unstaged、untracked，划定本批来源文件与生成输出；说明受影响页面、访客可完成的动作和必须保持的路由。视觉任务保留目标、前态和比较视口。
2. **修改正确来源。** 按上表接入 Owner，连续完成内容、布局、交互、响应式和失败/空态。保持无 JavaScript 的基础内容、语义和键盘可访问；不手工修生成 HTML 来掩盖模板问题。
3. **形成候选后集中验收。** 按下表检查生成结果与实际页面；检查真实导航、搜索、筛选、折叠和移动菜单中本次受影响路径。只有观察到的失败或关键前提疑点才触发中途定向检查。
4. **核对成果和记录。** 技术、功能、视觉结果分别写结论；动态与交互保留实际操作证据。重大重构执行既有独立成果审计，补修后只补受影响范围。
5. **交接。** 检查生成器是否带来本批范围外变化，保留其他会话成果；补充有复用价值的问题。提交、推送和 Pages 发布状态分别报告，按本次授权执行。

## 集中验收怎么选

| 范围 | 适用检查 |
| --- | --- |
| 仅仓库维护文档 | 检查本批链接、命令、来源归属及 `git diff --check`；不改公开内容或触发站点构建 |
| 内容、模板、样式或前端行为 | `npm run check` → `npm run test:smoke` → `npm run package:site`，并对照批准基线查看实际浏览器结果 |
| 公开投影 importer | 既有 importer 的验证/测试与受影响页面；本地导入不证明源仓能力或线上部署 |

命令从仓库根运行；环境依赖使用当前 lockfile。`check` 中的 clean 会清理既有构建输出；共享工作区有其他会话产物时，先确认 Owner 或使用隔离副本。发布包验收放在 check 后重新生成，实际核对 `_site/` 的内容与隐私边界。

## 出错与恢复

保留失败命令、输入、视口、页面、日志和前后截图；先定位 JSON/生成、组件样式、运行时行为或环境问题。新样式保持 `hidden`、键盘、焦点和无 JS 合同。浏览器缓存、异步折叠和离屏渲染分别按实际状态诊断；不删除有效断言或更新批准值来容纳漂移。

生成检查失败时回到 Owner 修复；不覆盖用户内容、来源身份或同步许可。相关输入未变的通过证据可复用，首次失败命令保留原退出结果。
