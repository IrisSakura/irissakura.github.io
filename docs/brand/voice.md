# IrisSakura Voice

## 共同内容顺序

核心页面和项目叙事遵循：

```text
Value
System
Result
Evidence
Boundary
Next
```

先解释访客能获得什么，再说明系统如何工作和当前产生了什么结果。证据用于支撑结果，Boundary 用于限定结论，Next 给出继续查看、采用或联系的真实入口。Hero 不以 `EVIDENCE`、`VERIFIED`、`BOUNDARY` 等证明性词汇开场；这些信息保留在后续层级，不能被删除或改写成更高成熟度。

## Master

IrisSakura 的语气专业、清晰、克制，强调真实产出但不让审计术语压过作品价值。优先使用主动句和具体对象，避免“赋能、领先、全栈解决方案”等无法检查的宣传词。

## IRIS

Iris Engineering 的语气结构化、可执行、准确、状态明确。动词优先使用观察、授权、执行、验证、恢复；必须区分提案、授权、运行与完成。失败关闭是系统行为，不是 Hero 口号。

## SAKURA

Sakura Framework 的语气模块化、解释能力、强调组合与扩展，比 IRIS 稍温和。先说可解决的问题和最小采用路线，再说明 Public API、成熟度、已知边界与 Used By；Package 数量不等于生产成熟度。

## Journal 与 Games

Journal 采用研究式、问题导向的语气，允许不确定性，并明确 Observation、Reasoning、Application 与 Uncertainty。Games 由作品自己的世界、玩家体验与核心循环决定；站点只提供清晰案例结构，不把游戏文案强制改成工程审计口吻。
