# 已批准的界面美学契约

状态：现行约束。用户于 2026-10-29 确认 UI 统一方向，并要求后续工作保持该方向。实现基线为 `c1dcc3eb`；本文约束个人站的持续演进，不扩展到其他产品的界面。

## 要保持的整体感觉

以浅色纸面、克制边框、清楚的标题层级和统一交互为基础。人物、项目配色与内容图示承担辨识，正文和操作区域保持安静。插画可以活泼，操作规则必须稳定；保留创作者气质，同时让访客容易阅读、理解和行动。

项目之间允许不同构图。流程轴、模块分支、研究索引、工作台、作品展示和世界内容各自服务信息，不为追求统一而强行套进相同卡片网格。角色是否出现、采用哪个已批准资产，以当前 presentation 配置和任务约定为准；不得从历史截图擅自恢复已撤下的构图或素材。

## 共享角色与允许的变化

| 角色 | 必须保持 | 可以按内容变化 |
| --- | --- | --- |
| 按钮与输入 | 8px 圆角、1px 边框、至少 44px 高；主操作填色，次操作浅色；悬停不移动点击目标 | 宽度、排列、文案、项目强调色 |
| 主题标签 | 6px 圆角、12px 字号；列表、正文、侧栏和能力标签同一规则 | 文案、排列；状态徽章保留状态语义 |
| 文字卡片 | 12px 对称圆角、20–28px 安全留白、细边框、无外部投影 | 列数、内容结构；选中模块可用内部色条 |
| 媒体表面 | 16px 圆角和轻微阴影，完整展示主要内容 | 画面比例、响应式布局、已批准的插画边框 |
| 折叠控件 | 同一旋转箭头、完整焦点区域、原生键盘行为 | 展开内容、标题、默认状态 |
| 项目标题 | 同一无衬线字体与响应式档位；1440px 为 56px，390px 为 36px | 标题文字与换行；首页姓名和长文章标题保留各自角色 |
| 颜色与图示 | 使用现有语义色和六项目 palette；文字与背景成对满足对比度 | 项目色、真实内容图示及已批准资产 |

尺寸指默认浏览器字号下的 CSS 像素。实现继续使用 rem/clamp，并尊重缩放和减少动态效果偏好，不得用固定截图尺寸阻止文字放大。

## 禁止重新引入的分歧

- 同一用途的按钮或标签因页面位置变成另一种形状、字号或反馈；不能换一个类名来规避共享组件。
- 普通文字卡片上的胶带、倾斜、放大单角、厚硬投影或悬停整块浮起。人物画框已有的装饰不构成向正文扩散的理由。
- 用无依据的超大标题、额外字体、大面积高饱和背景、持续漂浮或闪烁来制造项目区别。
- 把所有内容卡片化，或删掉项目人物、配色和内容图示来达成表面一致。
- 改了浅底却留下旧白字、隐藏焦点轮廓、让按钮覆盖 `hidden`、破坏无 JS 阅读或原生折叠行为。
- 因旧测试、历史规范或某张参考图的装饰更强，就恢复已经被本次统一取代的实现。

## 实现和变更边界

`docs/ui-components.md` 解释组件语义和所有权；`config/interface-contract.json` 保存批准的数值；`style/tokens/interface.css` 与 `style/components/interface.css` 实现这些规则。页面 CSS 只安排内容、密度和构图。禁止通过内联样式、无 layer 规则、`!important` 或重复组件皮肤越过最终共享层。

正常新增页面、文案、内容组件、窄屏换行和可读性修复，应在上述方向内连续完成。真正需要改变品牌方向、共享几何、标题角色或装饰强度时，先呈现明确的变化理由、受影响页面及对比方案，取得用户对新方向的明确决定后，再一并更新契约、实现和验收。不得为使当前改动通过而自动改写基线或移除断言，也不增加日常改动的逐文件审批。

## 如何判断没有偏移

- 单测检查批准的 token 和最终样式所有者；浏览器检查实际组件值、项目标题、无阴影卡片及选中态例外。整个网站一起变成胶囊按钮，也必须失败。
- 新的同用途组件须接入现有语义类与浏览器角色选择器。扩充测试覆盖，不复制另一套默认值。
- 涉及实际输出的变更，在可用候选形成后集中检查：目标参考、变更前后画面、桌面和窄屏、真实鼠标/键盘路径。重要视觉重构继续执行独立成果审计；纯文档或测试改动不伪造新的视觉验收。
- 无溢出、测试通过或截图像素接近，不能代替阅读顺序、视觉密度、项目识别和交互可理解性的判断。
