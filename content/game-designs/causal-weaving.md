## 0. 文档定位与原创性边界



“全球从未有人记录过某种游戏类型”无法被严格证明，因为不存在覆盖全部游戏、原型、论文和内部设计文档的完备数据库。



因此，本提案采用更可审计的判断标准：该类型必须具有独立的核心动词、完整的胜负结构、可持续扩张的内容单元，以及不依附于战斗、建造、探索或分支叙事的运行时闭环。



本文提出的“因果编织类游戏”应被视为一个原创宏观品类提案，而不是对绝对历史首创性的无依据声明。



---



# 1. 品类定义



## 1.1 名称



**因果编织类游戏，Causal Weaving Game**



玩家不是直接操纵角色、单位、城市或生产线，而是向一个由自治主体组成的世界发布“未来承诺”。



一项未来承诺描述：



- 当什么条件出现；

- 谁负有实现责任；

- 必须在何时产生什么结果；

- 哪些资源可用于履约；

- 谁必须见证或承认结果；

- 无法履约时应执行什么替代方案；

- 违约应产生什么长期代价。



世界不会机械执行玩家指令。角色、机构、生态过程或其他自治系统会评估承诺，提出履约方案，争夺资源，拒绝不利义务，钻取条款漏洞，传播或压制证据，并最终使承诺被履行、被曲解、被争议或被违反。



玩家的根本目标不是“控制现在”，而是：



> 使自己希望发生的未来，成为世界中最容易执行、最难否认、违背成本最高的未来。



## 1.2 核心玩家动词



该品类的一级动词不是移动、攻击、建造或选择对话，而是：



**发布、绑定、担保、授权、委托、修订、见证、追认、豁免、重组、转移和结算承诺。**



地图、角色、经济、外交、战斗和剧情都可以存在，但它们只是履约环境，不是品类本体。



## 1.3 独立成类的最低判定条件



一款游戏只有同时满足以下条件，才属于因果编织类：



1. 大部分有意义的玩家行为都在修改承诺、权限、证据、优先级或违约责任，而不是直接改变世界对象。

2. 同一承诺可以被多个主体以不同方法履行，具体执行方案不是预先固定的。

3. “事情在物理上发生”与“事情被相关主体承认为已经发生”是两个不同状态。

4. 承诺失败不会只返回一个错误状态，而会生成持久的因果债务并改变后续世界。

5. 胜利取决于建立可抵御扰动的未来保证，而不仅是完成一次性任务。



只要这五点成立，即使游戏没有战斗、地图探索、资源生产或分支剧情，也能独立形成完整产品。

# 2. 代表性设计范式：可执行承诺操作系统



## 2.1 承诺不是脚本



普通规则的形式是：



> 若 X，则系统保证执行 Y。



因果承诺的形式是：



> 若 X 成立，发行者承诺在时间窗口 W 内使 Y 成立，并为此抵押资源、权威或信誉；世界中的主体可以接受、拒绝、变通或争议这一承诺。



因此，承诺具备以下性质：



- 描述目标结果，而不是固定操作序列；

- 必须有发行者和责任归属；

- 可能因资源、知识、权限或主体意愿而失败；

- 可以被不同计划实现；

- 需要满足特定的证据和承认条件；

- 违约后继续影响世界，而不是从任务列表中消失。



这使其区别于自动化编程、单位命令、任务系统和预制剧情分支。



## 2.2 五阶段闭环



### 阶段一：承诺



玩家构造一个结构化的未来约束，包括触发条件、目标状态、责任主体、时间窗口、抵押物、见证条件和退路。



### 阶段二：竞标



符合条件的自治主体评估该义务。



“竞标”不一定意味着货币拍卖。它可以表现为：



- 角色提出所需报酬；

- 机构要求获得某项权限；

- 派系要求交换政治让步；

- 生态过程要求特定环境条件；

- 自动系统报告其执行成本和失败风险。



### 阶段三：实现



系统将被选中的履约方案编译成具有前置条件、资源预留、持续时间和失败模式的执行计划。计划在世界中实际运行，而不是瞬间结算。



### 阶段四：见证



物理结果发生后，相关观察者接收信息，并依据证据、信任和解释规则判断承诺是否成立。



“完成”至少分为两层：



- **物质完成：** 目标世界状态已经形成；

- **承认完成：** 规定的见证者接受该状态足以满足承诺。



### 阶段五：债务



未完成、部分完成、逾期完成、以禁止方式完成或未被承认的承诺都会产生因果债务。



债务可能表现为：



- 信誉下降；

- 后续承诺抵押要求上升；

- 主体拒绝再次参与；

- 原有承诺失去优先级；

- 机构合法性受损；

- 依赖该承诺的其他计划连锁失效；

- 对手获得重新解释事实的机会。



债务不是单纯惩罚，而是下一轮玩法的输入。

# 3. 设计支柱



## 3.1 未来是可执行合同，不是预测结果



玩家不能直接选择结局，只能构造一个使结局更易成立的约束网络。



## 3.2 所有行动都会形成责任



传统策略游戏中，下错命令主要损失资源。在因果编织中，每次发行承诺都会制造潜在负债。越有力的承诺，违约后果越严重。



## 3.3 自治主体履约，而不是服从



主体必须拥有能力、知识、利益和风险判断。玩家可以设计激励和权力结构，但不能把主体降格为无条件执行器。



## 3.4 事实与承认分离



港口被疏散，不代表所有机构都承认疏散合法；协议被签署，不代表边境部队已经收到消息；目标人物死亡，不代表继承机构接受其死亡证明。



这层分离是本品类最重要的内容生成器之一。



## 3.5 失败必须继续运行



正常玩法失败包括无人接单、资源冲突、计划中断、证据不足、见证者拒绝和期限逾期。这些都是领域事件，不是程序异常，也不应强制玩家读档。

# 4. 核心游戏对象：承诺



## 4.1 字段组成



### 身份信息



- 承诺 ID；

- 发行者；

- 所属机构；

- 创建时间；

- 当前版本；

- 可见范围。



### 触发条款



- 触发谓词；

- 触发观察来源；

- 最早生效时间；

- 防重复触发策略；

- 撤销条件。



### 角色绑定



- 责任主体；

- 受益主体；

- 受影响主体；

- 可替代履约者；

- 有否决权的主体。



### 目标结果



- 必须成立的世界谓词；

- 可接受的结果范围；

- 禁止采用的实现方式；

- 结果持续时间。



### 时间约束



- 开始窗口；

- 完成期限；

- 宽限期；

- 争议期；

- 最终确认时间。



### 经济与权力



- 可动用资源；

- 可授予权限；

- 对履约者的激励；

- 发行者抵押物；

- 最大可接受附带损失。



### 见证条款



- 哪些主体必须观察；

- 什么证据有效；

- 是否需要法定人数；

- 是否允许代理见证；

- 对相互冲突证言的处理方式。



### 弹性与退路



- 哪些条款可以放宽；

- 放宽顺序；

- 替代目标；

- 失败时的补偿方案；

- 是否允许转移责任。



### 违约策略



- 债务类型；

- 债务规模计算；

- 责任归属；

- 对依赖承诺的传播规则；

- 是否允许追认或补救。



## 4.2 承诺状态机



推荐状态序列：



**草拟 → 已验证 → 休眠 → 已武装 → 已触发 → 已绑定 → 规划中 → 已预留 → 执行中 → 物质完成 → 待承认 → 已履约**



异常或分支状态包括：



- 有争议；

- 部分履约；

- 已逾期；

- 已违约；

- 已豁免；

- 已取代；

- 已撤销；

- 无可行计划。



必须保留“物质完成”和“已履约”之间的独立状态，不能直接合并。



## 4.3 示例承诺



### 承诺 C-104：北港撤离



| 字段 | 内容 |

|---|---|

| 触发 | 潮位模型报告未来六小时内超过警戒值 |

| 对象 | 北港常住人口 |

| 目标 | 第十二时片结束前，所有对象离开危险区域 |

| 禁止方式 | 不得以强制拘押方式迁移 |

| 见证 | 港务局和码头工会必须分别确认 |

| 资源 | 运输预算 200，临时征用权 2 级 |

| 抵押 | 发行机构信誉 30 |

| 弹性 | 可以改变运输方式，不得改变安全区标准 |

| 退路 | 主要道路关闭时允许调用水路撤离 |

| 违约 | 生成公共安全债务和劳资信任债务 |



同一个承诺可能由轮渡、私人车辆、临时铁路、步行通道或分区撤离实现。承诺定义结果边界，不指定唯一答案。

# 5. 运行时总体架构



推荐采用“逻辑离散、表现连续”的可暂停实时架构。模拟以固定时片推进，界面以更高帧率插值表现。



主数据流：



**玩家意图 → 命令网关 → 承诺编译器 → 触发网络 → 义务市场 → 有界规划器 → 冲突仲裁与资源预留 → 事务执行器 → 观察与见证层 → 履约结算与债务账本 → 事件日志与投影模型 → 玩家界面**



## 5.1 分层结构



### 第一层：权威模拟内核



负责时间、实体、物理资源、事务提交和确定性事件顺序。只有这一层能够最终改写权威世界状态。



### 第二层：因果操作系统



负责承诺、义务、依赖、优先级、冲突、预留、违约和债务传播。



### 第三层：自治主体生态



负责角色、机构、群体和环境过程的目标、能力、知识、信任、竞标和履约行为。



### 第四层：认知与见证层



负责信息传播、观察权限、证据质量、主体信念、争议和最终承认。



### 第五层：预测与解释层



负责影子模拟、风险等级、因果解释、瓶颈分析和玩家可读的未来投影。



### 第六层：内容与扩展层



负责条款类型、动作算子、角色原型、场景规则、主题包和版本迁移。



## 5.2 状态所有权原则



系统必须遵守以下不变量：



1. 只有事务执行器可以改写权威世界状态。

2. 每次状态变化都必须对应一个不可变领域事件。

3. 每个领域事件都必须带有原因 ID 和关联 ID。

4. 规划器、竞标器和预测器只能读取不可变快照。

5. 工作线程只能返回提案，不能自行提交结果。

6. 物质完成不能自动等同于承诺履约。

7. 同一资源在重叠时间窗内不得被重复预留。

8. 所有随机决策必须来自可重放的分区随机流。

9. 次级触发默认推迟到下一时片，防止同一时片无限递归。

10. 界面状态不得反向成为模拟事实。

# 6. 核心模块职责



## 6.1 命令网关



接收玩家的发布、修订、撤销、授权、拨款、豁免和证据提交操作。



职责：



- 验证结构是否完整；

- 验证发行者是否具有相应权限；

- 计算抵押和发行成本；

- 识别明显的循环引用；

- 返回可定位到具体条款的错误。



命令网关只验证命令是否合法，不判断承诺是否一定能够完成。一个困难甚至近乎不可能的承诺可以合法发行，但必须明确展示其风险和抵押成本。



## 6.2 承诺编译器



把高层承诺转换成运行时可执行结构：



- 触发订阅；

- 角色绑定查询；

- 目标谓词；

- 权限要求；

- 资源需求；

- 见证要求；

- 违约与退路分支；

- 依赖图边。



结构化编辑器是权威输入。自然语言可用于显示或辅助填写，但不能直接作为模拟真值，以免产生不可重放的语义漂移。



## 6.3 增量触发网络



跟踪可能影响承诺的事实变化。



不应每个时片全量扫描所有承诺。应为谓词建立依赖索引：



- 哪些事实字段变化会使谓词重新求值；

- 哪些实体类型可能成为绑定对象；

- 哪些时间边界需要唤醒承诺；

- 哪些证据事件可能结束争议。



适合采用增量匹配网络或编译后的谓词有向无环图。



## 6.4 义务生命周期管理器



承诺触发后，生成具体义务实例。



同一承诺可以因不同时间、区域或对象触发多个义务。生命周期管理器负责：



- 父子义务关系；

- 义务拆分和合并；

- 委托深度；

- 期限；

- 当前履约者；

- 完成比例；

- 争议状态；

- 终止状态。



## 6.5 主体资格与竞标模块



从世界中筛选可能履约的主体，然后生成竞标。



主体资格由以下因素决定：



- 能力；

- 所在位置；

- 已知信息；

- 可用时间；

- 权限；

- 当前承诺；

- 资源和装备；

- 与发行者的关系；

- 是否认同承诺目标。



内部竞标评分可以采用：



**预期收益 + 目标一致度 + 合法性收益 − 资源成本 − 风险 − 机会成本 − 信任惩罚**



模拟关键评分应采用定点数或量化值，以避免跨平台浮点差异。



每个竞标必须附带解释向量，例如：



- 能够在期限内完成；

- 要求额外运输权；

- 与现有义务冲突；

- 不接受禁止强制迁移条款；

- 对发行者信任过低。



## 6.6 有界计划编译器



规划器根据目标结果反向寻找可执行动作。



推荐采用受限的分层任务网络与目标导向动作规划混合模型：



- 动作算子声明前置条件、效果、持续时间、资源需求、观察特征和失败模式；

- 从目标谓词反向检索能够产生该结果的算子；

- 为算子绑定主体、位置和资源；

- 形成有向无环执行计划；

- 根据成本、风险、时间和冲突排序；

- 只保留有限数量候选计划。



规划必须有明确预算：



- 最大搜索深度；

- 最大展开节点数；

- 最大候选计划数；

- 单义务最大处理时间；

- 单时片总规划额度。



预算耗尽时，产生“规划预算耗尽”领域结果，而不是卡死模拟线程。



## 6.7 冲突仲裁器



不同承诺可能争夺同一主体、资源、地点、时间窗口或事实解释。



推荐仲裁顺序：



1. 世界硬性不变量；

2. 已生效的安全规则；

3. 权限与法定优先级；

4. 已确认的资源预留；

5. 明示的承诺先后关系；

6. 抵押和违约代价；

7. 综合计划效用；

8. 稳定、确定的最终排序键。



不能只使用一个“优先级数字”，否则玩家最终会把所有重要事项设为最高级。



仲裁结果必须生成可解释事件，指出哪些计划因何种资源、权限或事实冲突被拒绝。



## 6.8 资源预留系统



资源不只包括物资，也包括：



- 主体时间；

- 空间容量；

- 通行窗口；

- 权限额度；

- 信息渠道；

- 公众注意力；

- 政治资本；

- 见证者可用性；

- 信用和信誉抵押。



预留应具备时间区间、所有者、用途、可抢占性和释放条件。



执行前先预留，可以把“已保证”和“仅可能”明确区分。



## 6.9 事务执行器



事务执行器是唯一有权提交世界状态变更的模块。



每个计划步骤应经过：



**读取版本 → 验证前置条件 → 检查预留 → 计算效果 → 验证不变量 → 写入事件批次 → 原子应用状态差异 → 增加世界版本**



若任一步失败：



- 原子步骤完全回滚；

- 可分割步骤只保留已明确提交的子步骤；

- 释放未消耗预留；

- 生成对应的执行失败事件；

- 触发退路或重新规划。



## 6.10 观察、知识与见证模块



权威世界只保存“实际发生了什么”。不同主体拥有各自的信念视图。



为避免给每个主体复制完整世界，可使用认知分区：



- 直接观察范围；

- 所属机构共享频道；

- 地区公共信息；

- 私密通信；

- 传闻网络；

- 法定记录；

- 传感器或证据链。



一次事件首先产生物理事实，然后依据可见性路由为不同主体生成观察记录。主体再根据信任、知识和解释规则形成信念事实。



见证策略可包括：



- 直接观察；

- 可信代理；

- 多方见证；

- 法定人数；

- 权威机构确认；

- 证据链完整；

- 多个相互独立来源一致。



争议必须有终止机制。推荐设置“挑战窗口”：窗口内可推翻承认；最终确认后不回滚物理世界，只能产生新的赔偿、追责或合法性债务。



## 6.11 因果债务账本



债务至少分为：



- **资源债务：** 消耗或占用了尚未补偿的物资和时间；

- **信任债务：** 主体对发行者未来承诺要求更高抵押；

- **合法性债务：** 机构的授权范围和优先级下降；

- **语义债务：** 条款解释存在未解决矛盾；

- **时间债务：** 将未完成义务推迟给后续时片；

- **依赖债务：** 下游承诺因上游违约变得脆弱。



债务会沿承诺依赖图传播，但传播应具有衰减、上限和类型转换规则，避免一次小失败无限放大。



玩家可以通过补偿、重新谈判、公开承认、替代履约、债务转移或机构改革处理债务。



## 6.12 预测与解释模块



预测器不能修改世界，只能从不可变快照运行有限影子模拟。



不推荐直接显示伪精确概率。更适合展示以下等级：



| 等级 | 含义 |

|---|---|

| 锁定 | 必要资源已预留，已知冲突已解决 |

| 有支撑 | 存在可行计划，但仍依赖可变条件 |

| 脆弱 | 计划存在未预留依赖或单点故障 |

| 有争议 | 物质计划可行，但承认或权限存在冲突 |

| 无绑定 | 没有主体、资源或算子能够形成计划 |

| 硬性不可能 | 违反世界不变量或明确禁令 |



解释模块必须能回答：



1. 为什么发生了？

2. 为什么没有发生？

3. 哪个条件改变了结果？

4. 接下来最可能在哪个依赖点断裂？



## 6.13 事件日志与回放模块



事件日志保存：



- 事件 ID；

- 世界时片；

- 事件类型；

- 发起者；

- 目标；

- 原因事件 ID；

- 关联流程 ID；

- 输入世界版本；

- 输出世界版本；

- 状态差异摘要；

- 可见范围；

- 随机流位置。



存档采用“周期快照 + 追加事件日志”。加载时从最后一个有效快照重放日志尾部。

# 7. 关键数据模型



## 7.1 模型总览



| 模型 | 核心职责 |

|---|---|

| 世界实体 | 表示人物、机构、资源、地区与环境对象 |

| 权威事实 | 保存客观世界实际发生的状态 |

| 信念事实 | 保存主体或认知分区对世界的认知 |

| 承诺 | 描述尚未完成的未来责任结构 |

| 义务实例 | 表示承诺触发后的具体执行责任 |

| 计划 | 表示履约所需的步骤有向无环图 |

| 预留 | 锁定资源、主体时间、权限与容量 |

| 见证记录 | 表示观察者对履约证据的接受或拒绝 |

| 因果边 | 表示承诺与义务之间的依赖、互斥和替代关系 |

| 债务条目 | 表示违约后的长期资源、信任和合法性后果 |



## 7.2 世界实体



实体采用组件化结构。典型组件包括：



- 身份；

- 位置；

- 库存；

- 能力；

- 权限；

- 目标；

- 风险偏好；

- 当前承诺；

- 信任关系；

- 机构成员关系；

- 知识订阅；

- 观察能力。



## 7.3 权威事实



权威事实描述实际世界：



- 主体；

- 谓词；

- 对象或数值；

- 生效时间；

- 失效时间；

- 来源事件；

- 当前版本。



权威事实中不存放“某角色认为的概率”。



## 7.4 信念事实



信念事实属于特定观察者或认知分区：



- 观察者；

- 对应命题；

- 接收来源；

- 可信度；

- 接收时间；

- 是否被其他事实反驳；

- 是否已成为法定记录。



## 7.5 义务实例



义务是承诺触发后的具体运行对象：



- 来源承诺；

- 已绑定主体；

- 目标谓词；

- 截止时间；

- 当前状态；

- 父义务；

- 子义务；

- 当前履约计划；

- 物质完成度；

- 承认完成度；

- 当前债务暴露。



## 7.6 计划



计划应表示为步骤有向无环图，而不是简单线性队列。



每个步骤包含：



- 动作算子；

- 执行主体；

- 输入条件；

- 预期效果；

- 时间区间；

- 资源预留；

- 可见性；

- 失败分支；

- 补偿步骤；

- 对其他义务的影响。



## 7.7 预留



预留记录：



- 资源；

- 数量或容量；

- 起止时间；

- 所属计划；

- 所属承诺；

- 是否允许抢占；

- 抢占代价；

- 当前状态。



## 7.8 见证记录



见证记录包含：



- 观察者；

- 被观察事件；

- 接收到的证据；

- 观察方式；

- 解释结果；

- 是否接受为履约证据；

- 可挑战期限；

- 可信度来源。



## 7.9 因果边



承诺和义务之间需要显式依赖边：



- 前置依赖；

- 资源依赖；

- 权限依赖；

- 信息依赖；

- 见证依赖；

- 互斥关系；

- 补偿关系；

- 替代关系。



依赖图应支持强连通分量检测。循环承诺不是一律禁止，但循环必须存在外部启动资源，否则应标记为“无初始驱动力”。

# 8. 单时片执行流程



每个模拟时片按固定阶段运行。



## 阶段 1：接收命令



冻结本时片玩家命令。命令按稳定顺序验证，不允许界面调用直接穿透模拟状态。



## 阶段 2：推进环境



处理时间、天气、自然衰减、移动完成和上一时片已安排的外部效果。



## 阶段 3：增量求值触发条件



只重新计算受变化事实影响的承诺谓词。



## 阶段 4：生成和更新义务



为新触发承诺实例化义务；处理期限、取消、豁免和替代关系。



## 阶段 5：确定候选履约者



根据能力、知识、权限、位置和可用性筛选主体。



## 阶段 6：生成竞标



主体评估义务并提交有解释的履约条件。



## 阶段 7：编译候选计划



规划器从竞标和动作算子中生成有限计划集合。



## 阶段 8：仲裁冲突



处理资源、主体、时间、权限和目标冲突。



## 阶段 9：提交预留



为被选中计划锁定必要资源。无法预留时，计划不得被显示为“锁定”。



## 阶段 10：执行到期计划步骤



事务执行器验证并原子提交效果。



## 阶段 11：传播观察



将事件路由到能够观察或接收消息的主体。



## 阶段 12：履约结算



分别求值物质条件和承认条件。



## 阶段 13：更新债务、信任和合法性



处理违约、部分履约、争议和补偿。



## 阶段 14：生成投影视图



更新未来状态、冲突摘要、解释链和界面读取模型。



次级事件默认进入下一时片。只有明确注册为即时反应的事件可以在当前时片继续传播，并受最大因果深度和事件预算限制。

# 9. 一次完整流程示例



玩家发布“北港撤离承诺”。



1. 潮位事实变化，触发网络激活承诺。

2. 系统生成“撤离全部居民”“保证非强制”“获得双机构见证”三个相互关联的义务。

3. 轮渡公司、运输工会和地方守备队提交竞标。

4. 守备队方案最快，但会违反非强制条款。

5. 轮渡方案合法，但轮渡同时被补给承诺预留。

6. 仲裁器决定保留部分补给船，释放两艘轮渡，并调用私人车辆补足容量。

7. 规划器形成分区撤离计划。

8. 执行中，一条道路塌方，原计划步骤失败。

9. 事务执行器保留已完成撤离结果，回滚未执行的道路运输步骤，并触发水路退路。

10. 所有居民最终离开危险区，物质条件完成。

11. 港务局接受证据，但工会认为部分工人受到隐性胁迫，拒绝见证。

12. 承诺进入“物质完成、承认有争议”状态。

13. 玩家可以支付补偿、公开调查、修改认定标准，或接受部分违约。

14. 处理方式将影响工会以后是否愿意参与玩家发布的承诺。



这里没有传统意义上的唯一正确路线。核心玩法是构造一个能在环境变化、资源冲突和解释争议中仍然成立的承诺网络。

# 10. 模块通信与并发模型



## 10.1 四类消息



### 命令



表达玩家或外部系统希望发生什么，例如：



- 发布承诺；

- 修订条款；

- 增加抵押；

- 委托机构；

- 提交证据；

- 豁免债务。



命令可以被拒绝，不具有既成事实效力。



### 领域事件



表示已经发生的事实，例如：



- 承诺已发行；

- 触发已命中；

- 义务已激活；

- 竞标已提交；

- 计划已选择；

- 资源已预留；

- 步骤已执行；

- 见证已接受；

- 承诺已违约。



领域事件不可修改。



### 查询



只读获取当前状态、历史、解释或投影。查询不得产生副作用。



### 提案



规划器、竞标器和预测器在工作线程中产生的临时结果。



提案必须包含：



- 基于哪个世界版本；

- 输入哈希；

- 生成模块；

- 有效时限；

- 稳定排序键。



主模拟线程在提交前重新验证。版本过期的提案直接废弃或重新计算。



## 10.2 并发模型



- 主模拟线程独占权威状态；

- 规划、竞标和预测可以并行读取冻结快照；

- 工作结果统一在阶段边界合并；

- 合并顺序由稳定键决定，不能依赖线程完成先后；

- 随机流按“场景种子、时片、承诺 ID、模块阶段”分区；

- 界面只读取投影模型，不能直接遍历正在修改的世界状态。

# 11. 可扩展点



## 11.1 条款扩展



可以新增：



- 触发谓词；

- 角色绑定条件；

- 时间窗口类型；

- 结果接受策略；

- 见证政策；

- 违约策略；

- 弹性规则；

- 抵押类型。



条款计算应尽量是纯函数：输入快照和参数，输出求值结果与解释，不直接修改状态。



## 11.2 动作算子扩展



每个新算子必须声明：



- 能产生什么效果；

- 需要什么前置条件；

- 哪些主体可以执行；

- 持续多久；

- 消耗和占用什么资源；

- 事件是否可被观察；

- 可能如何失败；

- 失败后是否需要补偿。



扩展不能绕过事务执行器直接写世界组件。



## 11.3 仲裁政策扩展



不同题材可以使用不同优先规则：



- 法律优先；

- 军事命令链；

- 宗教誓约；

- 市场出价；

- 家族继承；

- 生态承载力；

- 机器权限层级。



仲裁策略必须输出原因，不允许只返回一个获胜计划 ID。



## 11.4 见证体系扩展



主题可以把“见证”替换为：



- 法律签章；

- 新闻传播；

- 神灵认可；

- 传感器证明；

- 群体共识；

- 科学复现；

- 区块记录；

- 祖先记忆。



底层仍然保持“事件发生”和“相关系统承认事件”分离。



## 11.5 主体模型扩展



履约主体不必都是人物。它可以是：



- 公司；

- 家族；

- 国家机关；

- 群体；

- 物种；

- 自动机器；

- 天气系统；

- 交通网络；

- 分布式算法。



非人格化系统中的“竞标”可以理解为系统报告其可实现条件和成本。



## 11.6 内容包与版本管理



内容包需要声明：



- 包 ID；

- 依赖关系；

- 模型版本；

- 新增条款；

- 新增算子；

- 新增事件；

- 存档迁移器；

- 确定性兼容等级。



脚本扩展应运行在受限沙箱中，禁止文件、网络和非确定性时钟访问。核心规则优先使用声明式数据。

# 12. 失败隔离



## 12.1 区分玩法失败与引擎失败



### 玩法失败



包括：



- 无人竞标；

- 计划不可行；

- 期限逾期；

- 资源被抢占；

- 见证拒绝；

- 债务爆发。



这些必须转化为可继续游玩的领域状态。



### 引擎失败



包括：



- 脚本异常；

- 非法空引用；

- 事件模式不匹配；

- 存档损坏；

- 事务不变量被破坏。



这些必须被回滚、隔离或中止当前提交，不能伪装成玩法结果。



## 12.2 隔离措施



### 承诺预检沙箱



新承诺在激活前可运行一次不提交状态的预检，报告硬冲突、无可用算子、无可能见证者和明显循环。



预检只能报告当前已知条件，不能保证未来一定成功。



### 事务边界



每个动作步骤或明确声明的原子步骤组具有独立事务边界。异常时回滚到边界前状态。



### 规划熔断



规划器达到搜索预算后立即停止，返回当前最佳候选或无计划结果。



### 因果深度限制



每个事件携带因果深度。超过上限的即时事件进入下一时片，防止触发器互相递归。



### 每时片事件预算



超过预算的非关键事件排入后续队列。关键事务事件不得静默丢弃。



### 扩展包隔离



某扩展算子异常时：



1. 当前事务回滚；

2. 记录包 ID 和算子 ID；

3. 禁用该算子；

4. 将相关义务标记为需要重新规划；

5. 核心模拟继续运行。



### 非关键模块降级



预测器、图形化因果视图或统计模块崩溃时，权威模拟不应停止。界面可退化为基础状态列表和事件日志。



### 存档恢复



快照和日志段应带校验和。加载失败时：



1. 定位最后一个有效快照；

2. 重放有效日志段；

3. 截止到第一个损坏事件；

4. 明确报告丢失范围；

5. 不静默生成替代状态。

# 13. 调试、可观测性与测试



## 13.1 因果追踪器



开发者和玩家都需要看到一条可读链路：



**承诺为何触发 → 谁被绑定 → 谁提交竞标 → 为什么选择该计划 → 哪个资源被预留 → 哪一步失败 → 谁观察到什么 → 为什么接受或拒绝 → 债务如何传播**



每个节点应支持跳转到对应实体、事实、事件和条款。



## 13.2 “为什么没有发生”查询



普通日志擅长解释已发生事件，却不擅长解释缺失事件。系统应显式记录候选被淘汰的原因：



- 没有匹配主体；

- 主体不知道该义务；

- 权限不足；

- 前置事实不成立；

- 资源时间窗冲突；

- 计划搜索预算不足；

- 竞标效用低于阈值；

- 仲裁失败；

- 见证条件未满足。



## 13.3 规划器检查器



显示：



- 展开的目标；

- 使用的动作算子；

- 被剪枝的分支；

- 剪枝原因；

- 搜索预算消耗；

- 候选计划排名；

- 预期与实际执行差异。



## 13.4 资源时间线



展示资源在不同时间窗中的预留、占用、释放和抢占关系。它是定位双重预留和隐性瓶颈的主要工具。



## 13.5 确定性回放



同一场景种子、命令流和内容版本必须生成相同状态哈希。



回放检查点应保存：



- 世界状态哈希；

- 活跃承诺哈希；

- 预留表哈希；

- 债务账本哈希；

- 随机流位置。



## 13.6 自动测试



最低测试集合包括：



- 条款求值单元测试；

- 动作算子前置与效果测试；

- 事务回滚测试；

- 资源不可重复预留性质测试；

- 承诺状态机性质测试；

- 事件循环模糊测试；

- 存档迁移测试；

- 长时间债务传播稳定性测试；

- 多线程提案合并确定性测试；

- 固定场景黄金回放测试。



关键性质示例：



- 未发生物质效果时，承诺不能进入物质完成；

- 未满足见证策略时，承诺不能进入已履约；

- 已提交的原子事务不得处于部分应用状态；

- 被取消的已激活承诺必须结算取消责任；

- 投影模拟不得改变权威世界版本。

# 14. 玩家体验设计



## 14.1 核心感受



玩家应感到自己不是“操控一群棋子”，而是在建造一种未来秩序。



成熟阶段的满足感来自：



- 一个承诺即使遭遇意外仍能通过退路完成；

- 不同机构自发承担义务；

- 早期建立的信誉降低后续协调成本；

- 一个原本脆弱的目标逐渐变成不需要玩家干预的稳定惯例；

- 对手即使不愿配合，也发现违背承诺比履行更昂贵。



## 14.2 每分钟循环



典型短循环：



1. 查看未来压力和即将到期义务；

2. 找出最脆弱的依赖；

3. 发布或修订一项承诺；

4. 检查竞标和反对意见；

5. 增加资源、调整见证条件或重新分配责任；

6. 观察计划在世界中执行；

7. 处理意外、争议和债务；

8. 将一次性成功固化为长期制度。



## 14.3 界面必须呈现的信息



每张承诺卡至少显示：



- 当前状态；

- 触发条件；

- 剩余时间；

- 物质完成度；

- 承认完成度；

- 当前履约者；

- 已预留资源；

- 未解决依赖；

- 可能否决者；

- 抵押物；

- 最大违约暴露；

- 当前预测等级。



未来视图不应只画一棵庞大分支树。更适合使用：



- 承诺时间线；

- 因果依赖图；

- 资源冲突带；

- 主体竞标列表；

- 争议与证据面板；

- 债务热区；

- “保持不变时将发生什么”基线投影。



## 14.4 信息公平



失败可以来自未知信息，但系统必须明确区分：



- 已知安全；

- 已知风险；

- 明确未知；

- 被某主体隐瞒；

- 玩家本可通过调查发现。



不能把尚未模拟的内容伪装成角色隐瞒。



## 14.5 教学顺序



1. **单一承诺：** 一个发行者、一个履约者、一个结果、一个期限；

2. **资源冲突：** 两个承诺争夺同一主体或资源；

3. **多方案履约：** 同一目标出现不同执行计划；

4. **见证与争议：** 物质完成不再自动结算；

5. **债务与补救：** 玩家学习处理违约，而不是读档；

6. **制度化：** 玩家创建能自行发行、委托和追认承诺的机构；

7. **自维持网络：** 玩家从处理单个事件，转向设计可承受持续扰动的因果宪法。



## 14.6 难度增长方式



难度不应主要通过提高数值或缩短倒计时实现，而应通过增加：



- 相互依赖的承诺；

- 权限重叠；

- 信息不对称；

- 见证者意见分裂；

- 资源时间窗冲突；

- 主体机会成本；

- 对手对条款的策略性解释；

- 长期债务传播；

- 突发环境扰动。

# 15. 胜利、失败与长期进程



## 15.1 胜利条件



最终胜利不是让某个目标瞬间成立，而是建立一个稳定包络：



- 指定世界不变量持续成立；

- 关键承诺得到有效承认；

- 债务低于上限；

- 系统面对预定扰动仍能恢复；

- 玩家不需要持续微观修补。



示例：



> 北港在连续四个风暴周期中保持无人伤亡，撤离制度被三个互不隶属的机构承认，且公共信任债务不超过 20。



## 15.2 软失败



软失败包括：



- 一项承诺违约；

- 某机构退出；

- 见证被否决；

- 债务大幅增长；

- 原有制度需要重组。



软失败继续产生新局面。



## 15.3 硬失败



硬失败只应在系统性条件下发生：



- 玩家失去发行任何有效承诺的权威；

- 因果债务进入不可恢复的连锁违约；

- 所有关键主体拒绝与玩家建立责任关系；

- 场景核心不变量永久不可恢复；

- 世界进入明确终局状态。



## 15.4 进程结构



长期成长不宜表现为单纯数值升级。更适合解锁：



- 更复杂的条款；

- 更可靠的证据机制；

- 新的机构形式；

- 委托和责任转移能力；

- 多级见证制度；

- 债务重组工具；

- 跨区域承诺；

- 能自动发行子承诺的制度模板。

# 16. 防止退化为其他品类



## 16.1 防止退化为自动化编程



承诺不能保证执行，主体能够拒绝或提出条件；完成还依赖权限、资源、信任和见证。



## 16.2 防止退化为传统任务系统



任务通常由系统发布、玩家执行。这里的承诺主要由玩家构造，且可以由任何符合条件的主体以不同方式完成。



## 16.3 防止退化为即时战略



玩家不能绕过承诺系统直接连续下达单位动作。紧急命令也应建模为高成本、短期限、强制性的特殊承诺。



## 16.4 防止退化为互动小说



结果不是从预写分支中选择，而是由事实、资源、主体决策、动作算子和见证规则动态生成。



## 16.5 防止退化为城市经营



经济和机构可以存在，但玩家主要优化的是责任、依赖、认可和违约结构，而不是建筑布局或产量。



---



# 17. 主要退化策略与系统约束



## 17.1 承诺刷屏



约束方式：



- 发行占用有限权威容量；

- 每项承诺需要抵押；

- 同时活跃承诺增加协调成本；

- 无意义承诺不会产生等额信誉收益。



## 17.2 在失败前撤销



承诺一旦触发，撤销必须生成取消债务。越接近期限，责任越高。



## 17.3 所有事项设最高优先级



优先级不能独立决定仲裁。还需考虑权限来源、既有预留、抵押、承诺年龄和违约传播。



## 17.4 循环委托



委托深度必须有上限。原始发行者不能通过无限转包完全逃避责任。



## 17.5 伪造见证



证据需要来源、传递链和挑战窗口。被揭穿的伪证应产生比普通违约更高的信任和合法性债务。



## 17.6 用低价值承诺刷信誉



信誉收益应与承诺影响、真实风险、履约独立性和重复程度相关，并具有递减收益。



## 17.7 依赖预测器寻找完美答案



预测只展示有限视野和已知条件。对未知主体意图、未来扰动和争议信息使用明确的不确定标记，不提供全知解。

# 18. 内容生产范式



该品类的基础内容单元不是“关卡”，而是一个**压力生态**：



- 一组具有不同目标和权限的主体；

- 一组稀缺资源；

- 一套动作算子；

- 一套见证规则；

- 一组相互冲突的初始承诺；

- 若干动态扰动；

- 一个需要长期维持的稳定目标。



场景设计者不必预写所有解决路径。主要工作是确保：



- 目标至少有三种结构明显不同的实现网络；

- 每种网络有不同债务暴露；

- 关键主体之间不存在单一万能关系；

- 物质完成与承认完成会在至少一个节点分离；

- 意外事件能迫使玩家使用退路或重组责任。



可适配题材包括：



- 神话誓约；

- 外交条约；

- 企业治理；

- 灾害协调；

- 星际殖民；

- 家族继承；

- 生态修复；

- 司法调查；

- 分布式机器社会。

# 19. 最小可行垂直切片



## 19.1 原型范围



建议首个原型严格控制为：



- 一个港口聚落；

- 四个机构；

- 二十四个重点主体；

- 三个聚合人口群体；

- 六类资源；

- 十二类结构化条款；

- 十八个动作算子；

- 三种见证策略；

- 三类因果债务；

- 一个四十五至六十分钟场景；

- 四十八个逻辑时片；

- 两类外部扰动。



## 19.2 原型暂不包含



- 自然语言直接生成权威承诺；

- 开放式动作生成；

- 无限规划深度；

- 多人同步；

- 大规模个体级人群模拟；

- 可随意修改底层状态的脚本模组。



## 19.3 原型验收标准



- [ ] 移除直接单位控制后，游戏仍然完整可玩。

- [ ] 同一核心目标至少存在三种不同履约网络。

- [ ] 至少一种成功方案不是设计者预先指定的固定序列。

- [ ] 所有失败都能追踪到具体事实、资源、主体或见证条件。

- [ ] 承诺违约后产生新的可玩决策，而不是只能重开。

- [ ] 相同种子与命令流能够稳定重放。

- [ ] 规划器超时不会阻塞模拟。

- [ ] 预测模块停用后，核心游戏仍能运行。

- [ ] 玩家能够区分物质完成、承认完成和最终履约。

- [ ] 游戏后期的主要挑战来自承诺网络，而不是数值膨胀。

# 20. 可迁移到其他游戏的设计思想



## 20.1 将意图保存为持久数据



传统输入通常执行后即消失。把玩家意图保存为带期限、责任和状态的实体，可以为策略、角色扮演和经营游戏提供更强的因果连续性。



## 20.2 分离事实与被相信的事实



该思想可以迁移到：



- 潜行游戏中的敌人认知；

- 推理游戏中的证据接受；

- 战略游戏中的外交认知；

- 角色扮演中的声誉和传闻；

- 生存游戏中的群体恐慌。



## 20.3 用责任约束替代直接控制



玩家不直接命令角色，而是设定目标、权限、激励和责任。这能显著增强自治角色的可信度。



## 20.4 将失败设计成债务



失败不必删除进度。它可以留下未来成本、关系裂痕、资源缺口和制度负担，使失败本身成为内容。



## 20.5 让自治决策产生解释



AI 不只输出“做什么”，还应输出：



- 为什么愿意做；

- 为什么拒绝；

- 需要什么条件；

- 什么因素会改变决定。



这对任何含自治角色的游戏都适用。



## 20.6 将计划视为提案，而不是状态修改



异步规划、寻路、AI 和预测模块都只返回带版本的提案，由权威线程重新验证后提交。这种模式可迁移到大型模拟、多人同步和可回放游戏。



## 20.7 为复杂系统设计“为什么没有发生”



缺失事件通常比已发生事件更难调试。系统性记录候选淘汰原因，可以同时改善开发调试和玩家理解。



## 20.8 用最终确认窗口限制无限追溯



允许事实在短期内被争议，但在明确窗口后进入最终状态。该方法能在动态叙事与系统稳定之间取得平衡。



## 20.9 用韧性而不是瞬时完成衡量胜利



要求玩家构建能吸收扰动、自我修复的系统，比单次达到数值目标更能体现长期策略质量。



## 20.10 让非关键系统可降级



预测、可视化和统计工具可以失效，但核心模拟仍继续。这种失败隔离原则适用于所有复杂运行时。

# 21. 总结



**因果编织类游戏**的独立性来自一个现有宏观品类通常不具备的基本关系：



> 玩家编辑的不是对象，也不是动作序列，而是世界对未来结果承担责任的方式。



其代表性设计范式“可执行承诺操作系统”以结构化承诺为输入，以自治主体竞标和有界计划为执行机制，以物质事实与社会承认的双重结算为结果，以因果债务作为持续反馈。



完整闭环为：



**定义未来责任 → 寻找可能履约者 → 编译可执行方案 → 在真实世界中承担冲突与失败 → 让结果被观察和承认 → 结算债务 → 将临时成功固化为稳定制度**



该品类最重要的玩家体验不是“我赢得了一次行动”，而是：



> 我构造了一种即使世界反抗，也会继续把目标推向成立的秩序。
