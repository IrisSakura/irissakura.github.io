# 双重收敛：大逃杀中的有效空间、存活人数与终局密度控制

> 系列：游戏系统的共同语言
>
> 日期：2026-08-11
>
> 状态：草稿
>
> 核心问题：一场几十甚至上百名玩家、地图又非常巨大的比赛，怎样在保留落点与搜刮自由的同时，稳定地从低密度探索阶段推进到高密度终局？

[系列目录](../blog.html)

大逃杀刚开始时，玩家往往相距很远。

有人落在城市。

有人选择地图边缘。

有人刚刚找到第一把武器。

有人还在建筑之间搜索弹药和护甲。

如果系统什么都不做，这种大地图多人比赛并不会自然变得越来越精彩。

相反，它很可能出现两种极端。

一种是玩家长期分散：

- 很长时间没有遭遇；
- 大量时间用于无事件移动；
- 玩家为了安全一直躲避；
- 比赛迟迟无法结束。

另一种是所有高价值资源集中在少数区域：

- 大量玩家开局同时落在热点；
- 前几分钟淘汰大量参与者；
- 中后期反而人口稀疏；
- 比赛节奏从“极度拥挤”突然坠落成“长时间找不到人”。

因此，大逃杀真正困难的设计问题并不是：

> 怎样做一个不断缩小的圆。

而是：

> 怎样控制整场比赛的玩家密度曲线。

## 先说结论：大逃杀是一套空间与参与资格共同压缩的比赛收敛系统

**双重收敛（即“地图和人数一起往终局压”）**：随着比赛推进，同时减少玩家可以安全活动的有效空间，以及仍具备当前比赛参与资格的玩家数量，使原本分散的多人状态逐步收敛到高密度终局。

这两条轴分别是：

```text
空间收敛
Safe Playable Area
↓
↓
↓

参与者收敛
Alive Players / Alive Squads
↓
↓
↓
```

最终形成：

```text
较小的有效空间
+
较少的存活玩家
=
可控的终局冲突密度
```

这里最重要的并不是：

```text
圈越来越小
```

或者：

```text
玩家越来越少
```

而是两者之间的比例。

## 有效玩家密度比“还剩多少人”更能解释比赛节奏

**有效玩家密度（即“当前这块地方到底有多挤”）**：当前仍具备比赛资格的玩家数量，相对于当前真正可活动、可通行和可战斗空间所形成的宏观密度。

可以先使用一个非常粗略的概念表达：

```text
EffectivePlayerDensity
≈
AlivePlayers
÷
EffectivePlayableArea
```

它不是一个足以直接决定平衡的完整公式。

真实比赛还会受到：

- 地形；
- 建筑；
- 高低差；
- 河流；
- 山体；
- 可通行道路；
- 载具；
- 队伍分布；
- 视野；
- 掩体；
- 信息传播距离；

影响。

但这个指标能解释一个很关键的现象：

> 剩余玩家减少，并不意味着比赛一定越来越安静。

如果空间缩小得更快，玩家密度仍然可能不断增加。

反过来，如果玩家淘汰速度远快于安全区压缩速度，即使比赛只剩二十人，地图仍可能显得非常空旷。

所以安全区设计真正应该关注的是：

```text
玩家密度曲线
```

而不是孤立关注：

```text
每一圈的半径
```

## 缩圈不是伤害墙，而是比赛节奏控制器

**比赛收敛系统（即“把所有人逐渐推到一起的规则”）**：通过改变合法生存区域、未来路线和空间价值，持续提高玩家发生有效交互概率的宏观控制机制。

最粗糙的理解是：

```text
圈外掉血
→ 玩家必须进圈
```

但如果只做到这一点，Safe Zone 仍然只是一个伤害区域。

真正完整的职责包括：

- 缩小有效地图；
- 提高玩家密度；
- 迫使长期隐藏者重新移动；
- 周期性改变安全路线；
- 重新评价建筑、高地和交通节点；
- 让“继续搜刮”和“提前转移”形成取舍；
- 把比赛从资源阶段推向位置阶段；
- 保证终局一定能够发生；
- 最终让所有可行策略承担决战风险。

因此，安全区本质上是一种宏观调度器。

它调度的不是某个 NPC 或任务。

它调度的是整场比赛中所有玩家的空间行为概率。

## 大逃杀的典型节奏可以拆成三个主导阶段

从玩家决策重点来看，一场比赛通常会经历：

```text
Loot Dominant
→
Rotation Dominant
→
Position Dominant
```

也就是：

```text
资源主导
→
转移主导
→
位置主导
```

### 资源主导阶段

玩家首先关心：

- 有没有武器；
- 弹药够不够；
- 护甲等级；
- 治疗数量；
- 是否拥有基本交战能力。

此时地图空间很大。

玩家密度相对低。

系统重点是保证：

> 玩家尽快获得行动资格，同时让不同落点产生有意义的风险收益差异。

### 转移主导阶段

随着下一安全区公开，玩家开始关心：

- 离圈多远；
- 什么时候出发；
- 哪条路线更安全；
- 是否还能继续搜刮；
- 是否需要载具；
- 路上可能遇到哪些队伍；
- 应该打圈边还是提前抢中心。

此时，装备提升仍然重要，但空间决策开始压过单纯搜刮。

### 位置主导阶段

终局阶段，绝大多数玩家的基础装备已经成型。

新的价值中心变成：

- 高地；
- 掩体；
- 建筑；
- 转移路径；
- 投掷物；
- 敌人位置；
- 未来移动圈方向；
- 谁先暴露。

也就是说，比赛的核心资源发生了转换：

```text
物品
→
时间
→
路线
→
位置
→
信息
```

高质量的大逃杀不是始终让玩家做同一件事情。

而是让系统逐步改变：

> 当前什么资源最值得争夺。

## 落点是双重收敛发生前的第一次风险投资

比赛甚至在玩家获得第一把武器之前就已经开始。

**落点投资（即“用开局风险换资源和未来路线”）**：玩家用初期遭遇概率、资源质量和未来转移成本进行的一次预先交换。

热点区域通常具有：

```text
高资源
+
高玩家密度
+
高早期淘汰风险
```

边缘区域则可能是：

```text
低竞争
+
较完整搜刮时间
+
更高未来转移成本
```

交通枢纽可能提供：

```text
中等资源
+
更多未来路线
+
更高经过流量
```

因此，落点不是纯粹的：

> 我喜欢去哪里。

它实际上决定了玩家最早承担哪一种风险。

如果所有高价值资源都平均分布，落点决策会变弱。

如果所有高价值资源又只集中在一个热点，开局可能退化成：

```text
所有人都知道那里最赚
→ 大量玩家重复落同一个位置
```

合理地图应该让不同落点交换的是不同风险，而不是只有一个明显最优答案。

## 搜刮承担的是单局临时构筑，而不是长期资产积累

大逃杀中的装备系统通常服务当前 Match。

玩家从低资源状态开始：

```text
缺乏完整战斗能力
→ 获得第一件可用武器
→ 建立基础攻击与防御
→ 补充弹药和治疗
→ 优化武器组合
→ 优化配件
→ 构筑趋于成熟
```

这与撤离式游戏有重要差别。

撤离式系统的核心是：

```text
带长期资产入场
→ 局内获得新资产
→ 成功撤离
→ 提交到长期仓库
```

大逃杀则更接近：

```text
低资源入场
→ 临场构筑
→ 用当前构筑竞争
→ Match 结束
```

因此大逃杀中的 Loot 设计重点不是长期资产保值，而是：

> 玩家在有限比赛时间里，以多快速度获得“足够参与”的战斗能力，又以多大空间继续优化自己的临时构筑。

## 随机性应该改变解决方案，而不是取消行动资格

**受约束随机（即“东西可以不同，但不能什么都没有”）**：保留搜刮结果的不确定性，同时保证基础战斗能力、区域总价值和关键资源不会频繁落入极端不可玩状态。

随机 Loot 能让同一个落点每局不同。

但它存在一个非常明确的边界。

玩家可以接受：

```text
我只找到普通步枪
对面找到了更适合近战的武器
```

很难接受：

```text
对面获得完整武器
我搜索了数栋建筑后仍然完全没有战斗能力
```

前一种情况改变玩家解决问题的方式。

后一种情况可能直接取消解决问题的资格。

因此可以对随机结果施加：

- POI 最低武器数量；
- 区域 Loot 总价值预算；
- 武器与对应弹药的关联；
- 高级物品与高风险区域绑定；
- 极端低价值连续结果保护；
- 基础战斗能力保底；
- 高价值内容保持随机。

受约束随机不是为了让所有人开局完全公平。

它只是控制：

> 随机性可以制造劣势，但不要频繁制造没有行动权的状态。

## 每次战斗都会向地图广播信息

普通竞技游戏中，一场交火首先是两个队伍之间的问题。

大逃杀中不是。

**战斗信息泄露（即“开枪等于告诉附近的人这里有事”）**：玩家战斗产生的枪声、爆炸、技能、载具和淘汰信息，会改变附近其他玩家的决策概率。

一次交战会消耗：

### 物资

- 弹药；
- 护甲；
- 治疗；
- 技能；
- 投掷物。

### 时间

战斗持续越久，安全区可能越近。

### 注意力

参与双方都更难观察第三方向。

### 信息

战斗会暴露：

- 大致位置；
- 武器类型；
- 持续时间；
- 交战规模；
- 可能存在的残血目标。

于是：

```text
A vs B
```

并不是封闭事件。

附近 C 队可能听到枪声：

```text
A vs B
→
A vs B vs C
```

更远的 D 队又可能根据枪声和淘汰信息继续靠近。

这就是大逃杀中常见的第三方介入。

## 第三方不是独立玩法模块，而是信息传播的自然结果

**第三方介入（即“打架会吸引下一队”）**：新的玩家或队伍利用既有交战产生的位置暴露、资源消耗和注意力缺口进入战斗。

它不需要一个：

```text
ThirdPartySystem
```

来强行生成。

只要系统真实存在：

```text
战斗
→ 声音传播
→ 信息暴露
→ 双方消耗
→ 战利品出现
→ 附近玩家重新评估收益
```

第三方行为就会自然形成。

但这里存在一个非常敏感的平衡边界。

如果第三方收益太高：

```text
主动开战
→ 双方消耗
→ 胜者残血
→ 第三方轻松收割
```

理性策略会逐渐变成：

> 永远不要第一个打。

这会损害整个比赛的主动性。

反过来，如果击杀后立即完全恢复：

```text
战斗结束
→ 瞬间满血满甲
```

第三方威胁又会几乎消失。

因此，战斗后的恢复窗口需要让：

```text
获胜
```

成为有价值结果，同时让：

```text
长时间暴露
```

继续具有代价。

可使用的手段包括：

- 快速护甲交换；
- 快速补充基础资源；
- 更低摩擦的战利品界面；
- 局部恢复；
- 击杀资源奖励；
- 合理掩体；
- 控制战斗平均持续时间。

这里真正需要平衡的不是单次击杀奖励。

而是：

> 主动交战在考虑第三方风险后，是否仍然是一种合法策略。

## 淘汰控制的是“还有多少人拥有比赛资格”

**参与资格收敛（即“还能继续竞争的人越来越少”）**：通过死亡、淘汰和队伍退出，使 Match 内仍然具备胜利资格的参与者数量持续减少。

传统 Deathmatch 是：

```text
死亡
→
复活
→
重新参与
```

因此玩家数量基本稳定。

典型大逃杀则是：

```text
Alive
→
Downed
→
Eliminated
→
退出当前比赛资格
```

人数收敛的意义不仅是：

> 死一个少一个。

它与空间收敛共同决定比赛密度。

如果只有缩圈，没有真正淘汰：

```text
100 人
→
一直 100 人
→
区域不断缩小
```

终局会迅速变成无法控制的极端拥堵。

如果只有淘汰，没有缩圈：

```text
100 人
→
20 人
→
仍然在整张巨大地图
```

剩余玩家又可能长期互相找不到。

所以大逃杀需要两条收敛轴同时运行。

## 复活系统实际上是在逆向修改人数收敛速度

现代大逃杀经常加入：

- 倒地救援；
- 队友卡；
- 复活信标；
- 商店复活；
- 二次挑战；
- 阶段性重生。

这些机制可以减少：

```text
开局死亡
→
长时间只能观战
```

带来的组队体验问题。

但从宏观系统看，所有复活机制都在做同一件事：

> 放慢参与资格收敛。

因此，复活不是完全独立的外围功能。

它必须与比赛收敛节奏共同设计。

如果复活：

- 无限次数；
- 没有资源成本；
- 全阶段开放；
- 到处都能执行；
- 几乎没有风险；

那么：

```text
Elimination
```

会逐渐失去真正意义。

存活人数无法稳定下降，终局就会被拖长。

因此复活通常需要至少一种约束：

- 时间窗口；
- 使用成本；
- 专用地点；
- 暴露风险；
- 阶段限制；
- 后期关闭。

设计复活机制时，不应该只问：

> 队友救回来是不是更有体验？

还需要问：

> 它把整场比赛的人数曲线改成了什么样？

## 安全区设计的核心不是半径，而是时间预算

玩家看到安全区后，真正需要解决的是：

```text
距离
÷
移动能力
<
剩余转移时间
```

但玩家还要同时考虑：

- 是否继续搜刮；
- 是否绕开危险区域；
- 是否等待敌人；
- 是否需要车辆；
- 是否要抢中心；
- 是否沿圈边推进；
- 是否救援队友。

因此：

**转移预算（即“还剩多少时间处理这段路”）**：下一阶段安全区开始产生不可接受压力之前，玩家仍可用于搜刮、战斗和移动的有效时间。

如果第一圈过早开始：

```text
刚落地
→
立刻横跨地图
```

玩家原本的落点决策会被随机圈位置直接覆盖。

如果每一圈都过慢：

```text
搜刮完成
→
长时间无事可做
→
再慢慢移动
```

中期则会失去节奏。

所以每阶段安全区至少需要共同考虑：

```text
WaitDuration
ShrinkDuration
TargetAreaRatio
OutsideDamage
RevealLeadTime
TraversalDistance
```

它不是一个单参数系统。

## 提前转移与延迟转移应该同时具有合理收益

缩圈有意义的前提是：

> 玩家什么时候移动，是一个真正的决策。

提前转移意味着：

```text
放弃部分搜刮
→
换取更安全路线
+
提前占据位置
```

延迟转移意味着：

```text
继续获取资源
+
可能截击其他转移者
→
承担被圈追赶和路线封锁风险
```

如果提前转移永远更强：

```text
圈一公布
→
所有人立刻去中心
```

策略会收敛成唯一答案。

如果延迟转移永远没有风险：

```text
一直搜刮到最后一分钟
```

安全区又失去时间压力。

好的 Rotation 系统不是决定：

> 什么时候必须走。

而是让不同出发时间交换：

```text
资源
位置
路线
信息
安全性
```

## 圈中心和圈边代表的是不同信息结构

进入安全区后，还存在两种常见宏观策略。

### Center Play

提前进入中心。

主要收益：

- 下一阶段平均转移距离较小；
- 被安全区强迫大范围移动的概率较低；
- 可以提前经营强势地形。

主要风险：

- 敌人可能从多个方向接近；
- 需要长期防守位置；
- 更难确保身后安全。

### Edge Play

沿当前安全区边缘推进。

主要收益：

- 圈外方向通常可以减少一个威胁来源；
- 更容易确认已经清理的后方；
- 可以利用被圈追赶的敌人。

主要风险：

- 后续仍可能持续转移；
- 路线更容易被地形和其他队伍封锁；
- 错误判断后缺少时间重新规划。

二者本质上的差异不仅是位置。

还是：

> 玩家愿意用未来移动成本交换多少当前信息确定性。

## 下一安全区不能使用完全无约束随机

如果安全区真正随机选点，终局可能出现：

- 圈中心落在深水；
- 高度差无法跨越；
- 峭壁只允许单向进入；
- 终局几乎没有掩体；
- 一栋建筑天然控制全部入口；
- 大量区域根本不可通行。

这类结果虽然“随机公平”，却不一定具有可玩性。

因此更稳健的方式是：

```text
生成多个随机候选
→
检查地形约束
→
过滤非法结果
→
评估可玩面积
→
评估掩体和连接性
→
评估终局适配性
→
选择合法结果
```

**约束区生成（即“随机位置也必须先通过可玩性检查”）**：保留安全区位置的不确定性，同时使用导航、地形、连接和终局条件拒绝不可玩的候选。

可以评估：

- PlayableAreaRatio；
- CoverAvailability；
- Verticality；
- BuildingDensity；
- WaterRatio；
- TraversalConnectivity；
- FinalCircleSuitability。

这种模式与 Loot 的受约束随机其实属于同一个设计思想：

> 随机产生变化，但系统负责拒绝明显取消玩家决策权的结果。

## 圈外伤害的目标是让圈外策略最终不可持续

圈伤并不一定需要杀死大量玩家。

它真正需要保证：

```text
长期停留圈外
```

最终不是一个稳定策略。

早期阶段可以容许：

- 短时间继续搜刮；
- 绕路；
- 救队友；
- 临时利用治疗。

这样边缘落点仍然有意义。

但后期如果仍然可以：

```text
大量治疗
→
无限抵消圈伤
```

空间收敛实际上已经被绕过。

因此圈伤通常需要随着阶段提高。

最终目标不是：

> 圈外碰一下就死。

而是：

> 你可以短暂承担圈外成本，但不能把圈外永久变成另一块安全区。

## 移动终局用于打破静态位置垄断

如果最终圈只是：

```text
围绕一个固定中心
→
不断缩小
```

而中心恰好存在极强建筑或高地，提前占据该位置的一队可能获得过高确定性优势。

**移动终局（即“最后的安全位置本身也会移动”）**：终局阶段不再只减小面积，而是让可生存区域整体发生位移，迫使已有强势位置重新接受转移风险。

它可以：

- 迫使玩家离开终极掩体；
- 重新产生路线决策；
- 打破无限固守；
- 让剩余队伍重新暴露；
- 保证终局继续产生状态变化。

这不是为了让终局更“随机”。

它承担的是另一项职责：

> 防止一个静态空间答案永久终止后续决策。

## 终局的目标不是战斗最多，而是所有策略都必须承担风险

比赛最后阶段如果仍有：

- 大区域；
- 无限掩体；
- 无限资源；
- 无限治疗；
- 无限复活；

玩家可以继续延迟冲突。

因此终局通常会逐步：

- 缩小有效空间；
- 提高圈外压力；
- 使用移动圈；
- 关闭部分复活；
- 限制长期治疗拖延；
- 增加位置暴露。

但这里也存在另一种失败：

```text
区域过小
+
玩家过多
+
移动速度过快
```

会把所有策略压成纯粹反应和运气。

真正合理的终局不是：

> 一定要让所有人立刻打起来。

而是：

> 没有任何策略能够永远逃避最终风险。

## 双重收敛最好通过曲线而不是单点参数调试

大逃杀平衡容易陷入这样的工作方式：

```text
第一圈半径改小一点
第二圈伤害提高一些
武器数量增加 10%
```

这些参数当然需要调整。

但更值得观察的是整场 Match 的时间序列。

例如：

| 指标 | 需要观察的问题 |
|---|---|
| Alive Players by Phase | 人数是否过早或过晚收敛 |
| Effective Area | 空间压缩是否匹配人数下降 |
| Player Density Curve | 中后期遭遇概率是否持续增加 |
| Match Duration P50/P90 | 是否存在大量异常长局 |
| Final Zone Duration | 终局是否经常停滞 |
| Landing Heatmap | 开局是否过度集中于少数 POI |
| First 5 min Eliminations | 开局是否淘汰过多 |
| Loot-to-Combat Time | 玩家多久获得基础战斗资格 |
| Third-Party Frequency | 主动交战是否被系统性惩罚 |
| Outside Zone Time | 圈外是否成为长期可行策略 |
| Rotation Heatmap | 某些路线是否形成天然死亡通道 |

尤其值得关注的是：

**玩家密度曲线。**

理想状态通常不是简单线性上升。

但它应能体现：

```text
早期
分散、允许选择

中期
密度持续提高、冲突增加

终局
高密度、位置和信息成为核心
```

如果出现：

```text
开局极高密度
→
中期骤降
→
长时间无人相遇
```

问题可能不在某一把武器。

而在航线、POI 分布、缩圈和淘汰速度共同作用后的宏观曲线。

## 第三方比例也是比赛生态指标

如果大量战斗都是：

```text
2 队开战
→
立即第 3 队加入
→
立即第 4 队加入
```

则玩家可能逐渐学会：

> 不主动战斗才是最优解。

所以应该统计：

```text
2 队交战占比
3 队交战占比
4 队以上交战占比
```

并结合：

- 战斗平均时间；
- 战后剩余生命；
- 战后恢复速度；
- 枪声传播范围；
- 地图连接度；
- 玩家移动速度；

一起分析。

第三方本身不是需要消灭的问题。

它是大逃杀信息生态的重要组成部分。

需要控制的是：

> 它是否已经强到让主动行动失去价值。

## 玩家界面必须让收敛规则可预测

系统可以拥有复杂的密度控制模型。

但玩家需要看到的仍然应该非常直接。

圈信息至少应让玩家快速知道：

- 当前安全区；
- 下一安全区；
- 开始缩圈时间；
- 自己到安全区的距离；
- 当前圈伤强度；
- 预计是否来得及到达。

地图应该让玩家理解：

- POI 大小；
- 资源等级；
- 航线；
- 道路；
- 地形；
- 载具机会。

玩家死亡后，Death Recap 还应该帮助区分：

- 正面失败；
- 多方夹击；
- 第三方；
- 圈压导致的路线错误；
- 多个攻击者；
- 位置暴露。

收敛系统越强，玩家越需要理解：

> 自己是在哪一步被系统压力逼入这个局面的。

否则玩家感受到的不是战略后果。

而只是：

> 圈又刷我脸上了。

## 与相近类型的边界

| 类型 | 空间是否主动收敛 | 淘汰是否持续减少参与资格 | 单局主要目标 |
|---|---|---|---|
| 大逃杀 | 是 | 通常是 | 成为最后存活者 |
| 撤离式 PvPvE | 不一定 | 不要求收敛到唯一玩家 | 带资产成功撤离 |
| Deathmatch | 通常固定 | 通常死亡后复活 | 击杀或分数 |
| 生存游戏 | 世界通常长期存在 | 不以单局人数收敛为核心 | 长期生存与发展 |
| 英雄射击 | 通常固定目标区 | 通常复活 | 团队目标或比分 |

最容易混淆的是大逃杀和撤离式 PvPvE。

二者都可能拥有：

- 大地图；
- 搜刮；
- PvP；
- 不完全信息；
- 高死亡成本。

但宏观结构不同。

大逃杀的核心是：

```text
比赛结果收敛
```

撤离式游戏的核心是：

```text
资产结果提交
```

一个最终要求所有参与者逐渐被压缩到唯一胜者。

另一个允许很多玩家在不同时间主动离场，并把局内收益提交到长期经济。

## 这套机制不能直接照搬到所有多人游戏

双重收敛并不是一个通用的“多人游戏优化公式”。

它适合的前提是：

- 比赛有明确终点；
- 参与资格可以减少；
- 地图价值允许动态变化；
- 玩家接受被迫移动；
- 生存本身具有比赛价值。

如果游戏的核心乐趣来自：

- 长期占领基地；
- 稳定阵地经营；
- 反复死亡复活；
- 持续攻防；
- 长期资源积累；

强制空间压缩反而可能破坏玩法。

即使同为大逃杀，也不能直接复制某套圈参数。

以下因素都会改变合理曲线：

- 最大玩家数；
- Solo / Duo / Squad；
- TTK；
- 地图面积；
- 建筑密度；
- 移动速度；
- 车辆覆盖；
- 信息传播距离；
- 武器射程；
- 复活能力；
- 治疗能力；
- 英雄技能；
- 服务器 Tick；
- 平均战斗时长。

因此真正应该迁移的是：

> 用双重收敛设计比赛节奏。

而不是：

> 复制五个圈和一组半径。

## 我的双重收敛设计检查表

设计大逃杀宏观循环时，我会检查：

1. 开局玩家是否拥有足够空间选择不同风险路线？
2. 玩家落地后多久能够获得最低战斗能力？
3. 不同 POI 是否真的具有不同风险收益结构？
4. Loot 随机是否会频繁取消基础行动资格？
5. 当前有效空间缩小时，剩余玩家数量通常是多少？
6. 是否有 Player Density Curve，而不是只看 Circle Radius？
7. 中期是否存在长时间找不到人的低密度空窗？
8. 前五分钟是否淘汰了过多玩家？
9. 安全区是否给玩家足够的搜刮与转移准备时间？
10. 提前 Rotation 与延迟 Rotation 是否各有收益？
11. Center Play 与 Edge Play 是否都存在合理环境？
12. 安全区候选是否经过可通行性和终局可玩性验证？
13. 圈外伤害是否允许早期短期容错？
14. 后期圈外是否已经变成不可持续策略？
15. 战斗是否自然产生可被第三方利用的信息？
16. 第三方频率是否高到让主动战斗成为错误行为？
17. 战斗后是否拥有合理但不完全的恢复窗口？
18. 复活机制是否显著拖慢人数收敛？
19. 后期是否逐步关闭过强的复活和圈外拖延策略？
20. 最终圈是否容易被单一建筑或高地永久控制？
21. 是否需要移动终局重新制造位置变化？
22. 最终阶段是否仍然保留可理解的路线和掩体？
23. Death Recap 是否能解释圈、位置和多方介入的影响？
24. Match P50/P90 是否处于目标时长范围？
25. 每个阶段的 Alive Players 是否符合预期？
26. 是否记录 Landing、Rotation、Encounter 和 Third-Party 热图？
27. Final Zone 是否出现单位面积负载过高的问题？
28. 当前修改究竟是在解决局部数值，还是在修正整体密度曲线？

大逃杀最值得迁移的设计思想，不是“不断缩圈”。

而是：

> 一场大规模多人比赛需要主动的收敛机制。

系统首先允许玩家分散：

```text
选择落点
搜刮
判断风险
形成临时构筑
```

随后逐步压缩自由：

```text
公开下一圈
迫使转移
增加遭遇
产生淘汰
重新评价空间
```

最终再把比赛推进到：

```text
少量玩家
小型空间
高信息密度
高位置价值
不可逃避的最终风险
```

空间在收缩。

人数也在收缩。

真正被设计的，则是两者共同形成的比赛节奏。
